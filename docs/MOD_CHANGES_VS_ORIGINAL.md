# 원작과 다른 모드 규칙·훅 지점·UI 자료 기준

우리 모드가 원작과 다르게 만든 규칙, 원작 위에 건 훅 지점, 원작 UI 자료를 바꿀 때의 규칙을 모은다. 원작 사실은 `San14Sim/docs/orig`(라이브러리)에 두고, 모드 지침·정책·구현 기록은 여기와 `AI_TacticsMod/docs`의 기능 문서에 둔다(사용자 2026-11-15 "sam14sim은 라이브러리인데 거기에 우리 모드 지침 정리하지마").

2026-11-15에 `San14Sim/docs/orig`의 `rules_people.md` 4.2절과 "모드(원작 아님)" 줄 3개, `build_addresses.md` 8절, `ui_native.md` 6·7절과 충돌 C1~C3을 그대로 옮겼다. 주소 표기는 원문 그대로다(옛 = 이전 Steam 빌드, 새 = 1a4a447d).

## 1. 모드가 바꾼 인사 규칙 (원작 아님)

- 플레이어 자동등용 화면·다중 대상 통합(v8 자동등용_*·등용_다중대상_통합_조사.md): 733BD0 상태 갱신(옛), 선택창 vtable `13AC578`, 6CD040(옛)이 실행 무장 여러 명을 지원(원작은 "대상 1 : 실행 여러 명"). 컴퓨터·군단 AI 등용 후보 제외 `7B360`/`2CC50`(옛, 모드가 연결한 두 노드), 부상 보호(`injury`: 부상 무장 목록 제외·본초학 시정 자동 배치, local264부터 원작 시정 예산 `232500`·무장 코스트 `232350` 안에서만, 모자라면 모략 줄 무장을 뒤에서부터 뺌) — 모드 정책이며 원작 점수식은 바꾸지 않는다(v8 컴퓨터군단_등용시도제한.md, injury/부상보호_본초학.md, GITHUB_기능상세.md 3.4). 2026-11-15: 「외 N명」 추가 대상도 화면 대기 선택(layout+0x1E8, 0/10/30일)을 명령 +0x10에 그대로 싣는다(전에는 항상 0). 등용가능성 열(모드 추가)은 원작 `279DE0`을 굴림값 −1000000·실행 무장=군주로 불러 조기 '불가' 종료만 읽는다(점수 항이 상쇄돼 성패는 드러나지 않음). 원작이 불가라고 해도 모드 사실 판정(`personnel_recruitment_reason`)의 고정 사유(사관금지·충성 100↑·타세력 가족·군주 혐오)가 있을 때만 불가로 표시하고, 의리/5+충성>95 같은 거절은 '가능성 있음'으로 둔다(사용자 2026-11-15: 성패는 군사 조언으로만, 어떻게 해도 불가능한 경우만 알림). 일괄 등용의 차단 판정은 아직 모드 규칙(personnel_policy.h)이다.
- **모드(원작 아님)**: 논공 군주 친애(별도 저장·`22FDA0`·`234880`·`2A8D50`에 논공 관계 병합), 친애 500명 확장은 폐기된 설계(v8 논공_군주친애_구현기록.md, 친애500명_확장_구현기록.md). 개성 효과 0x6C(연계참가율)은 공감값에 합을 더함(`2A8D50` 계열).
- **모드(원작 아님)**: 명품창고(미분배 재고, 슬롯별 1개 규칙, 활동 중 수여, 외교 목록 필터), 저장 보조파일 `<native_name>.<hash>.warehouse`, 명품 전달 `1F16B0`(옛 1F0300)의 군주 군단 자원 사용(v8·awards/명품창고_활동중수여.md, research/campaign/경로_병참_교전_인구_열전.md). 슬롯·창고 규칙은 원작 규칙이 아니다.
- **모드(원작 아님)**: 논공 군주 친애 — 무공 1단계 +3000, 2단계 +3000(원작 효과표 500/500을 모드가 바꿈), 3단계는 병사 대신 현 군주와 상호 친애. 이적 `273100`(옛 2717D0) 성공 경로에서 `Person+1C2` u16(1C2·1C3 둘 다)을 0으로 초기화 → "미수여(0) → 다음 논공이 1단계". 관계 저장은 별도(`.merit` 보조파일), 전투·연계 전법 판정에도 병합(v8 논공_*).

## 7. 모드가 바꾼 전투 AI 규칙 (local226, 2026-11-18)

- 중립 방벽 돌파(`path_wall`·hit_response): 원작 공격 명령 6/11 앞에 relay 1번으로 서는 칸을 둔다. 서는 칸 = 원작 전투 반경(`2C9080`≠0 → 2, 아니면 1) 안이고 적대 세력의 완성된 망루(1~2칸)·투석대(2~3칸) 사거리(원작 `192110`/`2AD8F0` 거리 범위) 밖. 없으면 돌파하지 않는다(돌아갈 길이 없을 때만 예외). 순수 판단 `tower_reach::stand`(obstacle_policy.h).
- 누선 수리 공격(`ship_repair_strike`): 원작 전투가 반경 안 적을 모두 치는 점(KB rules_combat 1, 최대 3기록)을 이용해, 컴퓨터 누선을 공격 중인 시설과 그 수리 부대(행동 8/9, 대상 종류 11)가 함께 2칸 안에 드는 물 칸으로 옮긴다. 명령은 원작 setter(2ECEA0·2ECF00·2F05A0)로만 쓴다.
- 출진 편성(`sortie_formation`): 원작 계획 시험 실행(`sortie_probe`)에서 단일 명령 병사 ≥ 20,000이면 그 장수의 성에서 모드 편성으로 바꾼다(성 4만 조건 생략, 상한 = 원작 계획 합계).
- 컴퓨터 출진 전법(`ai_tactic_order`): 강한 전법 보유 장수 = 그 전법 + 교역전법(137·138·139 순) 최대 2개.
- 조타 지연 퇴각 순찰(`helm_delay_patrol`, local273): 원작 퇴각 전 지연 기간에 뒤집을 적 물칸이 없으면 대기 대신 항구(강 고리는 성) 12칸 안 물칸을 중계점으로 순찰. 조타 중계점·보충 중계점은 물칸만(둑 육지 금지). 고른 칸 어디로도 물길이 없으면 성의 다른 감시 지역·강 고리로 전환(`helm_noway_switch`). 명령은 helm_route(원작 setter)로만 쓴다.

## 8. 군사 알림함이 바꾼 알림 표시 (local273, 2026-11-20)
