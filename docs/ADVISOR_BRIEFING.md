모의·WARP 검사까지만 했고 실게임 확인은 아직 없다. 위 「구조 행」의 "같은 모양 행이 연달아 있으면 한 표, 문장이 끼면 나뉜다" 규칙은 이 절로 대체한다.
- **한 묶음에 종류별 표 하나.** `card_body`는 행이 있는 모든 메시지를 사이에 낀 문장과 상관없이 같은 모양끼리 한 표로 모은다. 표가 먼저(모양 순서 등용 R → 발견 D → 외교 P → 사절 E → 군사 M), 표로 만들지 못한 메시지는 그 뒤에 `• N일차 · 문장` 줄로 도착 순서대로 남는다(버리거나 추측하지 않는다). 표 안은 일차 순(같은 일차는 도착 순서 유지, 일차 모름은 `—`로 맨 앞).
- **일차 열 규칙.** 위 종류별 표는 모두 첫 열이 `일차`(`N일차`)다. 월별 수입과 지출 표는 군단·일자별로 이미 나뉜 묶음이므로 그대로 두고, 날짜는 제목 줄 `• N일차 · 군단`이 보인다(일차 열 없음). 이렇게 "합쳐지는 표 = 일차 열, 군단별 캡션 표 = 캡션"으로 일관한다.
- **행 모양과 열.** 모양 글자 + 4칸(안 쓰는 칸은 빈 칸): D 발견 `무장 | 장소 | 발견 | 결과`(장소·발견 열은 모든 행이 비면 빠진다), R 등용 `실행 무장 | 대상 | 도시 | 결과`, P 외교 `상대 | 안건 | 구분 | 결과`, M 군사 `부대 | 사유 | 조치`, E 사절 `세력 | 내용`.
- **문장에서 행 만들기(`parse_row`).** 게임 데이터가 아니라 원작 문구 틀(`San14Sim/origlib` msggame_exce)에서 도출했고 메시지 전체가 틀과 정확히 같을 때만 행이 된다. 한 줄 보고(`이름, 내용`): `X, Y 발견`(111/50077/51579, 금 줄 50079 제외) → D(결과 발견); `X, 장소의 탐색에 실패`(50089)/`탐색을 단념`(50100) → D(장소, 발견 없음, 결과 실패/단념); `X, Y의 등용에 성공/실패`(50065/50066/50161/50162) → R; `부대, 사유에 의해 퇴각`(12850)/`출진불가`(13508) → M; `A, B의 교환요청 승낙/거부`(13081/13088), `공격요청 승낙/거부`(12729/12740), `포로반환 승낙`(12752)·`반환요청 거부`(12764) → P(상대 B, 구분 `A 응답`); `A, B측과 동맹 (연장 )실패`(12708/12709) → P(구분 `A 제안`, 결과 실패). 여러 줄 사절 통지(50222): 줄을 이어 붙인 뒤 `[보고드립니다.] [말하는 이] X의 사자가 [Y께] 알현을 요청하였습니다.`/`뵙기를 청하고 있습니다.`/`찾아왔습니다.`/`방문했습니다.[ 만나러 가보시지요.]` → E(알현 요청 또는 방문). 역할이 분명하지 않은 `친선 성공/실패`(`A, B간의`), `공격요청 달성/미달성`, `X, Y에 항복`, 시 읊기, 상태 변화(`에 의해 상태가`)와 틀에서 벗어난 문장은 문장 줄로 남는다. 결과 낱말 색은 승낙·달성 녹색, 거부·단념·미달성 적색을 더했다.
- **외교 선택 뒤 자동 넘김 오류.** 원작 `CTreatDiplomacyState`(vtable 1460C48)에서 플레이어의 수락/거절은 YesNo 상태가 아니라 결정 창 자체의 입력이다: 3단계(`81CB90`)가 제안창을 띄우고 phase 6, 6단계(`817200`)가 창의 선택값(`+210/+220` 필드)을 읽어 응답 대화 상태(`CDialogGameStateBase<CCmnDlgMsgDialog_TreatDiplomacy>`, `804300`)를 쌓고 phase 9 또는 12/13으로 간다(`FUN_140813940`의 phase 분기, `0x4D8`). 모드의 수집 보호는 스택에 YesNo/Select/포로/입력 상태가 있을 때만 건너뛰었으므로, 선택 뒤 phase 12~15(결과 대사 `841660`, 확인 대화 `812FF0`)에서는 `dialogue_ready`가 참이 되어 줄을 화면 밖으로 옮기고 `83E300` 입력 대기의 타이머를 0으로 써 남은 대화를 모두 넘겼다. 수정: 플레이어가 응답자(교섭창 `+190`이 플레이어 세력)이거나 부모 위에 선택 상태가 쌓인 적이 있으면(`diplomatic_choice_parent`, 부모가 스택에서 빠지면 해제) 그 대화는 `diplomatic_scene`에서 `scene_decided`가 되어 **관찰만** 한다: 대사 텍스트와 외교 행은 브리핑에 저장하되 화면 이동·페이지 소비·닫기·타이머 0 쓰기를 하지 않아 원작 흐름(클릭으로 넘김)이 그대로다. 플레이어가 제안자(`+180`)이고 선택이 없는 대화(자기 제안의 결과)는 이전처럼 숨기고 넘긴다. 이 판정은 정적 분석이므로 `NO_RUNTIME_LOG` 밖 진단 로그 `advisor_diplomacy_skip(path, code, phase)`를 모든 판정 지점에 넣었다. path 0 확인 대화 입구, 1 결과 대사, 2 입력 대기 자동 확인, 3 확인 대화 프레임에서 포기; code 0 숨김·자동 확인, 1 부모 없음, 2 선택 상태 쌓임, 3 phase가 8/11/12~15 아님, 4 플레이어 결정(관찰만), 9 그 밖의 문(기능/수집/오버레이/튜토리얼). 다음 실게임에서 선택 직후 code 4가 찍히고 0이 없어야 한다.
- **검사.** 문장 틀별 `parse_row`(실제 문구, 색 코드, 줄 이음, 화자 이름, 깨진·애매한 문장), 사이에 낀 메시지가 있어도 한 표로 합쳐지는 `card_body`(일차 순·미상 일차·텍스트 뒤 배치·수입 캡션 유지), 외교: 응답자 대화 관찰만(입력 대기 타이머·페이지 불변), 선택 상태 → 선택 → 후속 대사 원작 유지 → 대화 끝 → 다음 대화 다시 자동 순서.
