# 진행 가속·빠른 저장·연출 단축

모두 `SAN14_Convenience.dll` 소유다. 현재 속도는 ×4/×8, 자동점령 연출은 약 1/4이다. 설치 버전과 배포 준비 상태는 CURRENT를 확인한다.

과거 v11.31의 ×2/×3.5 버튼·빠른 저장/로드 사용자 확인은 현재 ×8의 두 번째 프레임 호출 검증과 다르다. v12.9 실행 중 종료는 원인 미확인이며, 두 번째 프레임 호출과 자동점령 프레임 건너뛰기는 격리 후보다. 실제 현재 게임 진행·장기 안정성 확인은 남아 있다.

## 진행 속도 버튼 >>>>(×4), >>>>>(×8) — `src/native_speed_buttons.inl`
- 근거 `REA_Analysis/speed_20261018/README.md`. 팝업 `CChangeSpeedLayout`(vtable 1473DC8) 슬롯49 `882540` 뒤에 같은 순서로 버튼 id 8/10 생성(레이아웃 노드 8~11).
- 클릭: functor 꼬리점프 `898957`→`891720` 가로챔. 새 버튼은 원작 속도 2(>>>)를 고르고 배율만 기억(세이브 값 0~2 유지). **`5210E0`(라디오 선택)은 선택 버튼의 클릭을 다시 발생시키므로 클릭 처리에서 호출 금지**(무한 재귀로 멈춤 이력).
- 진행: `44BCA0`(vtable 슬롯 13D6698)의 단계0 카운터(+470)를 누산기로 0/1 설정한다. ×8은 첫 원작 프레임 처리 뒤 같은 모드·원작 속도2·모든 작업이 끝난 idle일 때 한 번 더 호출한다(프레임당 최대 2회 시작). 60fps 기준 ×4/×8이며 30fps에서는 최대 ×4다. 실제 하루 처리 비용에 따라 체감 배수는 달라진다.
- 호버: 팝업 호스트(vtable 14740F8) 슬롯1 `88C2E0`이 원작 버튼 3개만 비교 → 새 버튼 위면 비교 칸(+190)을 잠시 대체.
- 그림: 공통 스프라이트 표 `FEA5F28C`는 **게임이 원래 698개만 읽음**(뒤에 추가한 항목은 무시·엉뚱한 그림). >>·>>> 회색 4칸(207·208·212·213)을 새 그림으로 재지정하고 두 버튼 회색은 > 회색(202·203) 사용. 상태 노드 3=오버, 5·6=선택, 8·9·11=비활성.
- 자원 패치 `research/speed_buttons/build_patch.py` → `layout_patch/traits9_layout.{bin,json}`(개성 9칸 4개를 원래 오프셋 그대로 앞에 두고 아틀라스 `301526D7`, 표 `FEA5F28C`, 팝업 `40F993CE`, HUD `454A1BCC` 추가). **IDRK 엔트리는 마지막에 길이0 청크가 필수**(없으면 텍스처 로드가 끝나지 않아 검은 화면). 원본은 설치 직전 백업 인덱스에서 읽음.
- 설치기 `SplitManage.ps1` Reset: 이전 bank를 가리키는 우리 항목이면 오프셋 무관 복원(패치 크기 변경 대응).

## 빠른 저장 압축 — `src/save_codec.h`, `src/native_save_codec.inl`
- 근거 `REA_Analysis/save_20261018/`. 원작 `9321F0`/`932D40`(패트리샤 트리, 창 0x2000, 일치 3~0x200)이 로직 스레드에서 자동저장마다 약 1.7초.
- 형식: 헤더 0x1A43574C·원본크기·압축크기·순위표256, MSB 비트열, 코드 = n비트 접두(1…10)+n비트, 값=2ⁿ−2+접미. <0x100 리터럴, 이상은 거리=값−0x100, 길이=다음 코드+3.
- 교체: 호출 `933C5B` 하나. 해시 체인 압축 후 즉시 해제·비교, 다르면 원작 압축기. 해제는 게임 원래 함수(모드 없어도 로드 가능).
- 검사 `tests/save_codec_fixture.cpp`: 실제 자동저장 4개(원본 복원·순위표 일치·왕복) + 무작위 300건. 2.9MB 블록 약 110ms(원작 약 1.7초), 크기 약 +9%.
- 스위치 `기능설정.ini [game_flow] fast_save`.

## 묶음 스위치 — `기능설정.ini [groups]`
- `combat`(로더가 전투 DLL 미로드), `convenience`(0이면 편의 DLL은 조정만), `performance`(거리·이름 탐색·레이아웃 보관). 세 묶음 모두 꺼졌을 때만 기능 모듈을 생략한다. 세부 키의 현재 섹션과 상속은 [FEATURE_SWITCHES](FEATURE_SWITCHES.md).

## 레이아웃 보관 — `src/native_layout_wait.inl` (`[performance] layout_keep`, performance 묶음, 기본 켬)
- 최초 동기 로드 25~30ms, 참조 중인 레이아웃 재로드 2~3ms(진단 CSV 실측). 처음 5ms 이상 걸린 동기 로드 이름을 숨은 기본 CUILayout(`3F6BC0(0x178)`→`864C50`→vtable `1342530`→`92AB70(+0x130)`)에 비동기(`86C570` async=1, 부모 없음)로 한 번 더 로드하고 해제하지 않음(최대 512개). 2턴 실측: 반복 로드 대부분 2~4ms, HUD 재로드 기록에서 사라짐. 사용자 체감 "조금 개선".
- 타이머 1ms 요청(`[performance] timer_1ms`)은 측정상 효과 없음 → 기본 끔. 게임은 winmm을 임포트하지 않음.

## 자동점령 연출 단축 — `src/native_occupy_fast.inl` (`[game_flow] occupy_fast`, convenience 묶음, 기본 켬)
- 근거 `REA_Analysis/occupy_20261018/README.md`. `CEncirclingOccupationMovieState`(vtable `13D3F80`) 슬롯5 `42B7E0` 교체 + 카메라 호출 `42B507`(E8→`451360`) 교체.
- 카메라는 500ms 초과면 1/4, 125~500ms면 125ms로 줄인다. 점령 효과는 신호 없는 0x0E~0x1F 구간을 건너뛰고 마지막 신호 0x21 이후 0x24에서 완료 처리한다. 6·7단계 카운터는 프레임당 4씩 진행한다. 전체 연출은 원작의 약 1/4이며 천시 메시지는 유지한다. 현재 구현의 실게임 안정성과 체감은 별도 확인 대상이다.

## 남은 조사 (턴 전환)
- 레이아웃 동기 로드 `86C570`: 최초 로드 25~30ms(다른 스레드도 쉼 = 파이프라인 대기), 재사용 2~3ms. 단계 전환 때 HUD를 해제 후 재로드 → 진행 직후 약 1.2초, 보고창 생성 중 약 0.7초. 대기는 `14D90`이 단계를 직접 실행하며 잠금(`B2C0`/`B190`) 대기. 리소스 상주(참조 유지) 또는 단계 진행 원인 규명 필요.
- 10일째 후 보고 화면 전 약 3초: CPU 거의 쉼, 밀린 이동/피해 연출 재생 대기(원작부터 있던 현상). 연출 대기열 위치 미확인.
- 진단: `[diagnostics] layout_wait=1` → `data/diagnostics/layout_wait.csv`, CPU 기록 `optional_tools/AI모드_이름탐색AB측정_관리자.cmd`.
