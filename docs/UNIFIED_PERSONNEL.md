# 통합 인사·무장 검색·전법 선택

현재 배포에 포함된 시험 기능이며 설치기 기본값은 `[officer_ui] unified=0`이다. 편의 묶음이 필요하다. 아래 구현과 검사 이력은 실제 게임의 최종 배치·입력·저장 검증 완료를 뜻하지 않는다. 최신 설치 상태.

통합 인사, 일괄 작업, 플레이어 출진창 전법 우선순위는 모두 `SAN14_Convenience.dll` 소유다. 로더와 전투 DLL의 실행 코드(.text)는 기존 설치본과 일치한다.

진입 버튼만 무술대회 v30의 화면 출력 방식을 참고해 게임의 D3D11 뒷버퍼에 그린다. 버튼 크기의 작은 텍스처를 재사용하고 크기·강조 상태가 바뀔 때만 다시 만든다. 전체 화면이나 무장 목록을 별도 UI로 만들지 않는다. 창모드의 여백·해상도·클라이언트 좌표 변환을 처리한다.

클릭은 요청만 기록하고, 원래 게임 UI 콜백에서 `CDataSelectDlgBase<Data>` 무장 목록창을 연다. 검색 탭·체크 선택·일괄 작업·숫자/문자 입력은 기존 게임 창을 사용한다. D3D11과 창 입력 콜백에서 게임 함수를 호출하지 않는다. 표시와 입력 후 기존 화면 출력·게임 창 처리를 이어간다.

과거 승격 도구는 역사 보관 ZIP에 옮겼다. 현재 설치 여부는 `development/CURRENT.md`, 개발 근거는 `build/development/unified_personnel/`를 확인한다.

## 사용 흐름

전략 지도에서 진행 버튼 오른쪽, 명령서 아래에 통합 인사 버튼을 표시한다. 1920×1080 기준 좌표 (218,156), 크기 164×42이며 화면 비율에 따라 축소·이동한다. 버튼은 기존 UI의 크림색·갈색 계열에 맞춘다.

하나의 1920×1080 UI 안에 원작 목록 컨트롤 두 개를 나란히 배치한다. 왼쪽 무장일람은 (64,200)·1200×690, 오른쪽 검색 조건은 (1344,200)·496×690이다. 양쪽의 위쪽과 높이를 맞추며 각각 스크롤바를 둔다. 오른쪽 목록 컨트롤도 이 UI의 자식으로 직접 초기화하므로, 가운데 정렬된 전체 화면 목록창의 여백과 배경을 물려받지 않는다. 모든12탭의 열 합계가 왼쪽 폭 안에 들어오는지 검사한다. 글꼴과 목록 렌더링은 원작 그대로 사용한다.

상단 12개 탭은 무장 정보를 표시한다. 오른쪽에서 조건·이름·초기화 항목을 선택한 다음 하단 **선택 조건 변경**을 누른다. 조건이 바뀌면 원작 상태 전환으로 두 패널을 다시 열며 무장 선택을 유지한다. **일괄 작업**, **전법 우선순위**는 하단에서 연다. 이번 단계의 실제 좌우 배치·게임 입력은 설치 후 확인이 필요하다.

이름과 소속·능력·진형·전법·정책·개성·공로·주의·배우자·의형제·내면·연계 조건으로 플레이어 세력의 무장을 찾는다. 소속에는 빈 소유 성·관문도 표시한다. 소속은 현재 위치 기준이며 다른 플레이어 군단의 무장도 포함한다. 개성은 기존 9칸을 읽는다.

**연계 조건**은 실제 무장일람에서 기준 무장 한 명을 고른 다음 출진창과 같은 원작 등급 기호를 복수 선택한다. 기본 체크는 높은 세 등급(3~5)이며 변경할 수 있다. 친애·혐오 이름만으로 대체 판정하지 않는다. 왼쪽 연계 탭에는 원작 연계 기호와 부친·모친·배우자·의형제 열을 표시하도록 연결했다. 기준 무장 자신은 연계 등급으로 검색한 결과에서 제외한다. 비교 결과는 캐시하며 기준 변경·일괄 작업·창 재진입 때 폐기한다. 현재 우측 조건 행 방식은 임시이며, 상시 드롭다운 패널과 왼쪽 결과만 갱신하는 조작은 후속 구현 대상이다.

같은 조건에서 여러 값을 고르면 그중 하나, 다른 조건끼리는 모두 충족하는 무장을 표시한다. 능력 5종과 공적은 최솟값·최댓값을 포함한다. 검색을 바꿔도 선택을 유지하며, 현재 결과 밖의 선택 인원을 제목에 알린다. 현재 목록의 체크 인원은 원작 선택 표시를 사용한다. 조건 초기화와 선택 해제는 별도다.

| 일괄 작업 | 동작 |
|---|---|
| 집단편제 | 기존 10개 집단 중 하나에 최대 50명 저장. 군단을 넘어서 편제하며 기존 집단을 교체한다. 대상 검사가 끝난 뒤 반영한다. 기존 집단장이 포함되어 있으면 유지하고, 없으면 선택한 첫 무장을 집단장으로 삼는다. |
| 의형제 | 2~3명, 기존 의형제·혐오·임무 상태 검사. 원작의 맏형 ID 저장 구조와 결의 금 비용 사용. |
| 관직수여 | 선택한 빈 관직을 지휘병사 순, 무장을 공적 순으로 배정. 활동 중 무장의 기존 지휘 한도를 낮추지 않는다. |
| 명품수여 | 보관 중인 명품과 선택한 무장을 목록 순서대로 한 명에 하나씩 배정. 기존 보관함·수여 제한 사용. |
| 이동 | 소유 거점으로 기존 이동 임무를 등록. 출진·임무 중이거나 이미 목적지에 있는 무장은 제외. |
| 다중 전법 습득 | 여러 무장×여러 전법서. 이미 보유한 전법 제외, 공유 재고 예약, 보유 10칸이 찼으면 제외. 기존 전법을 덮어쓰지 않는다. |
| 교역 | 해당 교역 거점 보유 국가 선택, 무장당 금·군량·병사 공물 지정, 기존 교역 임무 등록. 확인창에 공물 최대 합계 표시. |

성공한 무장×행동마다 중앙군단 명령서 1개를 차감한다. 금·전법서·공물은 기존 함수가 소비한다. 의형제·집단편제는 전체 인원의 명령서가 있어야 실행하며, 나머지는 가능한 작업부터 처리하고 완료·제외·부족·실패 건수를 표시한다. 일괄 작업 직전에 확인창을 표시한다.

## 출진 전법 우선순위

통합창의 전법 우선순위에서 무력형(무력≥지력)과 지력형을 각각 설정한다. 고유·공용·교역 범주 및 개별 전법을 추가하고 위아래로 이동한다. 미보유·현재 진형과 호환되지 않는 전법을 건너뛰며 3개가 부족하면 보유 순서로 채운다.

자동 선택은 기본 해제 상태다. 활성화하면 플레이어 출진창의 대기 명령만 변경한다. 해당 창에서 이후 직접 고른 전법은 유지하며 무장·진형·설정이 바뀌면 다시 계산한다. 설정은 `data/unified_personnel.ini`에 원자적으로 저장한다. 게임 저장 형식은 추가하지 않는다.

## 검증 범위

- 필터·학습 계획·순위 28건, 전법 선택 콜백·설정 해석·관직 map ABI 13건, 네이티브 UI 비동기·취소·콜백 수명·주소 재사용·좌우 패널 92건, 실제 D3D11 픽셀·클릭·창모드 좌표 검사 23건 통과.
- 출진 연계 어댑터16건 및 현재 실행 파일의 원작 호출 경로·바이트 대조14건 통과. 원작 문자열·정렬·인자 방향·캐시 무효화를 검사했다.
- 두 패널의 수명·입력·위치92건 및 실제 원작 클래스·가상함수·크기 함수·전체12탭 너비30건 통과. 실제 화면 확인과는 구분한다.
- 실제 분리 DLL을 합성 이미지에 로드한 게시·원복 검사 통과. 통합 인사 훅은 편의성만 게시하고 전투 DLL은 원래 포인터를 보존한다.
- 기존 core 및 dll-split 경로의 출진·인사·논공·등용·명품 등 검사 통과. 세 DLL 빌드, 정적 편의 코드 연결, 로더 실패 처리, export 검사 통과.
- UI 경계 검사 55건 통과: 무장 검색·작업은 원작 창을 사용하고, 진입 버튼은 게임 화면 안에서 그린다. 전투·로더 실행 코드(.text)는 설치본과 일치한다. 이전 독립 창 미리보기는 최종 게임 UI의 화면 증거가 아니다.
- 최종 결과·소스/DLL 해시: `build/development/unified_personnel/candidate_verification.json`. 전체 빌드 로그: `build/development/bounded_panes_build_final.log`.

실제 게임의 버튼 표시·12개 탭 배치·문자 입력·키보드/컨트롤러 동작, 일괄 명령의 실제 소비·진행 결과, 집단/관계/임무의 저장 재로드는 확인 전이다. 네이티브 호출 ABI와 모의 검사는 원작 렌더링 확인을 대신하지 않는다. 원작의 의형제 후보 제약 전체와 교역 화면의 해금 조건 전체를 복제했다고 보장하지 않는다. 개발 후보와 실제 게임 검증 완료를 구분한다.

검사: `tools/check_feature.ps1 -Feature unified-personnel -List` 및 `-Build`. 공통 adapter 검사 선택은 `-Feature core -List`, 세 DLL 회귀 경로는 `-Feature dll-split -List`.
