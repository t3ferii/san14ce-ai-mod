# 조조전 인게임 조형 편집

첫 메뉴의 **조조전**에서 삼국지14 원작 선택 목록과 숫자 입력창으로 설정한다. Windows 팝업을 사용한 local1 방식은 더 이상 빌드하지 않는다.

- 진형 또는 세력 군주/군사를 선택 → 통솔 단계 선택 → 조형 목록에서 선택하면 오른쪽에 실제 2D 대표 그림 표시 → 원작 결정 버튼으로 초안에 반영.
- 목록에서 통솔 첫/두 번째 경계를 변경한다. 기본 경계 70 / 90, 기본 병종 표는 그대로다.
- 고유 무장에서 기존 92명 중 한 명을 골라 적용 진형을 체크한다. 체크하지 않은 진형은 공통 그림을 따른다. 장료 예시는 어린진·봉시진만 고유 그림이다.
- 최상위 목록의 **저장하고 닫기**로 저장한다. 최상위에서 취소하면 초안을 버린다. 하위 목록 취소는 이전 단계로 돌아간다. 기본값 복원도 저장 전까지는 초안이다.
- 수상·특수 진형의 원작 표시 제한, 능력치·전투 수식·세이브·깃발·지형 깊이·local14 정상/480×270 복구는 보존한다.

## 두 원본의 전체 조형과 메모리

원본 폴더는 읽기만 한다. 신조조전/조조전의 Unit_mov·Unit_atk·Unit_spc 각 1,500칸을 검사해 빈 칸을 제외한 **686 + 392 = 1,078개**의 전체 동작과 대표 그림을 추출한다. 이름이 확인되지 않은 그림은 원본명과 칸 번호로 표시한다. 서로 다른 원본 팔레트를 섞지 않는다. 대표 색상은 빨강이며 게임에서는 기존 세력색 처리를 사용한다.

파일 `assets/ccz/ccz_catalog.bin`은 35,170,623바이트. 최초 로딩은 목록/팔레트 약 28KB뿐이며 선택한 대표 그림과 실제 필요한 동작만 파일에서 읽는다. 사용자 요청(2026-11-02)으로 전투 GPU 그림 캐시를 256종으로 늘렸다. 사용하는 조형만 GPU에 만들며 아틀라스 데이터 상한은 약 24MiB다(팔레트·관리 비용 별도). 편집창을 나가면 미리보기 CPU/GPU 자원을 해제한다. 이는 전체 프로세스 메모리를 실게임에서 측정했다는 뜻은 아니다.

추출 도구는 `tools/ccz_build_catalog.py`, 모든 원본 파일 해시·개수는 `assets/ccz/ccz_catalog.json`에 기록한다. 기존 `ccz_units.bin`은 그대로 둔다.

## 설정·원작 연결

기존 `기능설정.ini`의 `[ccz_appearance] profile`만 쓴다. 버전 1 설정을 그대로 읽고 저장할 때 버전 2로 기록한다. 기존 병종 번호 0~189와 원작 모형 255는 호환되며, 신조조전 개별 칸은 0x1000+칸, 조조전은 0x2000+칸이다. 새 INI 파일은 없다. GUI/PowerShell 설치기는 숫자 목록 원문을 보존한다. DLL API 버전 2는 유지한다.

CTitleState 초기화 504670/프레임 50B800/퇴장 4F9310으로 첫 메뉴를 연결한다. 레이아웃 E7A28866의 추가 37/38번 노드와 기존 병합 14개 레코드는 그대로다. 편집은 `unified_dialogs`의 원작 데이터 선택/숫자 입력 경로를 사용한다. 원작 호출은 UI 스레드에서만 하며, 닫기 콜백 안에서 다음 창을 재진입시키지 않고 제목 화면 재개 후에 연다. 직접 게임 메모리에 원격 쓰기나 게임 함수 원격 호출은 하지 않는다.

그림은 캐시된 D3D 미리보기 패널로 원작 선택창 안의 빈 영역에 표시한다. 실제 런타임 경로는 `native_ccz_editor.inl`/`native_ccz_preview.inl`이다. 예전 `native_ccz_settings.inl`은 비교용 미사용 소스다.

## 검증 범위

ccz-sprites 검사: 두 원본 전체 항목의 해제/대표 그림, 진단·무로그 판, 실제 월드 아틀라스 디코더, 실제 팔레트와 미리보기 색상 일치, 네이티브 편집 상태 전이/취소/저장, WARP 미리보기와 퇴장 후 자원 해제를 확인한다. 원작 UI 호출을 가로챈 모의 검사와 WARP 검사는 실게임 실행을 뜻하지 않는다. 첫 메뉴에서의 실제 목록 배치·조작·선택한 조형의 실게임 표시는 사용자가 확인한다.
