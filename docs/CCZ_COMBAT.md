# 조조전식 막기·회심의 일격

## 2026-11-02 방향·비전투 발동 수정

현재 소유는 `SAN14_CCZ.dll`의 `native_ccz_sprites.inl`이며 편의 DLL은 기존 `169F8B` CALL을 게시한다. 원작 `1749A0`/`16FDD0` 저장본에서 공격자는 pair[0] 포인터, 방어자는 **pair+8 인라인 레코드**임을 재확인했다. 대상 레코드 해석과 최종 +20/+22 피해 수정 시점은 유지한다.

기존 코드는 서로 다른 유효 부대만 검사하고 적대 관계를 검사하지 않았다. 이제 종류27·ID1~500·Army vtable·원작 유효성·양쪽 생존 병력을 확인하고, `22CC40`의 세력 번호(u8 반환)와 `2CA280`의 원작 적대 판정(bool 반환)을 사용한다. 같은 세력·동맹·비적대·소멸 대상은 RNG, 상태 횟수, 연출, 추가 피해 변경 없이 원작 반환값과 피해를 보존한다. 두 함수의 앞48바이트는 CALL 가드와 함께 대조하고, 분리 fixture가 바이트 불일치 거부를 실행한다. 새 훅·ABI 항목·설정 키는 없다.

남은 횟수만으로 방어 자세·회심 섬광·「막기!/회심!」 문구를 계속 보여 주던 경로도 제거했다. 5회 규칙과 기존 날짜 만료는 유지하며, 실제 발동 시각부터 700ms만 해당 연출을 보인다. 마지막 횟수를 소비한 공격도 연출한다. 진단 로그 `ccz_combat_not_hostile`은 처음16개의 거부 세력쌍/방어 주장을, 기존 발동 로그 옆 `ccz_block_forces`/`ccz_crit_forces`는 공격·방어 세력과 피해를 기록한다. 새 진단 문자열은 배포 빌드에서 제외한다.

방향은 이동 벡터를 영구 우선하던 문제였다. 실제 로그의 이동 각도 -1.048과 원작 yaw5.235는 2π 차이로 일치한다. 정상 캡처와 선택적 원거리 캡처 모두 원작 display+744의 유한한 라디안 회전값을 우선한다. 이동 벡터는 원작 값이 유효하지 않을 때만 예비 값으로 사용한다. 원작 모델을 돌리거나 공격 대상을 재지정하지 않는다. `ccz_sprites_combat_facing`은 처음16개 제자리 전투 캡처를 기록한다. 병종 자산·깃발·UI·깊이 처리와 local14 `set_targets` 정상/480×270 복구 경로는 변경하지 않았다.

검사: `tests/ccz_battle_fixture.cpp`가 실제 모듈의 fix/capture/frame 코드를 모의 원작 함수와 실행한다. 아군·동맹·무효/소멸/비부대·0피해·다른 단계·스위치 OFF, 진짜 적의 막기/회심·5회 소모, 실제 제자리 캡처와 원거리 각도, 남은 상태의 가짜 연출 방지, 배포 진단 문자열 제외를 검사한다. 모의/정적 통과와 실게임 방향·발동 확인은 구별한다.

## 1. 넣을 자리 (근거 확인됨)

일반 공격은 `169C50`의 단계 처리로 진행된다 (REA, `REA_Analysis/damage_flow/gameplay_slice.pe` — DRM 해제 분석본에서 잘라낸 슬라이스, 원본 설치 EXE `87ed4e46…`). 전체 해제본은 `build/ui_native_analysis/editor83_plain/game.exe.unpacked.exe`(`1fbe6be7…`, 없으면 Editor V8.3 Steamless로 재생성).

| 단계 | 함수 | 역할 |
|---|---|---|
| 1 | `174BC0` | 시작/파성 경로 |
| 2 | `16A030` | 준비 |
| 3 | `16AB50` | 공격값(공군/공성) |
| 4 | `16A990` | 방어값 |
| 5 | `16A780 → 16A1D0` | 병사 피해 계산 → 출력 구조체 |
| 6 | `16FDD0` | 후속 보정. 조건이 맞으면 `+0x24=1`, `+0x22`=맵 값 |
| 7 | **`1749A0(manager, pair, output)`** | **피해 적용**: `output+0x20`·`+0x22`(u16) 합을 `178E30(피격종류, 피격id, 피해, 공격종류, 공격id)`로 병력에서 뺀다. 합이 0이면 원작이 1로 바꾼다. 끝에서 `2ECB80(피격부대, (+0x22≠0)+1)` 호출 |

- `pair[0]` = 공격자 기록, `pair+8` = 피격자 기록, 기록+4 종류 27 = 야전 부대. 부대 `+12` 주장, `+16` 병력, `+1A` 사기(u8). 실효 능력치 `22FCE0`.
- 예상 피해 표시(`7FA230` → `16A1D0`, [DAMAGE_PREVIEW.md](DAMAGE_PREVIEW.md))는 이 경로를 타지 않는다. 7단계를 바꾸면 **표시와 실제가 달라진다**(확률이라 표시에 넣지 않는 것이 맞다).
- 전법·계략·시설 공격은 별도 경로다(`1F9DE0`, `191760` 등). 1차는 **부대 일반 공격만** 대상으로 한다.
- `1749A0` 진입 훅은 **이미 SAN14_CombatAI.dll이 소유**한다(`native_obstacles.inl`의 `combat_apply_damage`). 새 훅을 걸지 않고 이 처리기 안에서 원본 호출 전에 `output`을 고친다.

## 2. 규칙 초안

판정 순서: **막기 → (막지 못했으면) 회심**. 공격자·피격자가 모두 야전 부대이고 주장이 있을 때만. 플레이어·컴퓨터 똑같이 적용.

```
d무력 = 피격 주장 무력 - 공격 주장 무력        (실효 무력, 22FCE0)
막기% = clamp(5 + 0.4·d무력, 1, 25)
막기 성공: output+0x20, +0x22 = 0  → 원작이 1명 피해로 처리

회심% = clamp(5 + 0.3·(공격 무력 - 피격 무력) + 0.2·(공격 사기 - 피격 사기), 1, 30)
회심 성공: output+0x20, +0x22 ×1.5 (u16·피격 병력 상한)
```

| 무력 차(방어-공격) | 막기% |
|---:|---:|
| −20 이하 | 1 |
| 0 | 5 |
| +20 | 13 |
| +40 | 21 |
| +50 이상 | 25 |

| 무력 차(공격-방어) / 사기 차 | 회심% |
|---|---:|
| 0 / 0 | 5 |
| +20 / 0 | 11 |
| 0 / +30 | 11 |
| +30 / +20 | 18 |
| +60 / +40 | 30(상한) |

조조전 원본 곡선(비율 1배=2%, 2배=20%, 3배=100%)은 삼14 능력치(1~100, 장수 간 비율이 작음)에서 거의 2~11%에 머문다. 그래서 **차이 기반 직선식**으로 바꿨다. 모든 계수는 설정값. 조조전 순발력 → 삼14 **무력**, 사기 → 부대 **사기**(+1A).

## 5. 연출 (조조전처럼 바로 알아보게)

조조전 막기·회심은 2D 스프라이트 전용 동작(`Unit_spc` 방어 3프레임, 회심 대사 741~746)이라 삼14 3D 부대 모델에 그대로 옮길 수 없다. 삼14 안에서 쓸 수 있는 수단을 우선순위로 둔다.

1. **원작 피격 반응 세기 재사용 (조사 중).** `1749A0` 끝의 `2ECB80(army, kind)` → `1C8940(army[0x148]+0x580, kind)`는 `obj+0x14 = max(obj+0x14, kind)` 만 한다. 즉 부대 표시 객체에 **피격 반응 단계(1 또는 2)를 예약**하고, 다음 그리기 때 반응 연출을 고르는 구조로 보인다. 원작은 반격/협공(`+0x22≠0`)일 때 2를 준다.
   - 회심: 2(또는 더 큰 값)를 예약해 큰 피격 반응 → 0단계에서 2보다 큰 값이 쓰이는지, `+0x14`를 읽는 그리기 함수가 값별로 무엇을 하는지 확인.
   - 막기: 반응 0(원작 호출 자체가 1을 넣으므로 막기 때는 1 유지 또는 생략).
   - 장점: 원작 애니메이션, 새 리소스 없음. 위험: 값 의미 미확정.
2. **머리 위 글자 "회심!"·"막기!".** 원작에 피해 숫자/상태 글자 팝업 함수가 있는지 REA로 찾는다(피해 숫자 표시 경로부터). 있으면 같은 UI 스레드에서 문자열만 바꿔 호출. 없으면 새 UI 작업이라 별도 단계.
3. **전황 메시지 한 줄.** "○○의 회심의 일격!" 같은 문구를 원작 전황 로그에 넣는다. 가장 쉽지만 눈에 덜 띈다. 1·2가 막히면 최소 보장용.
4. 효과음: 원작 효과음 재생 함수가 확인되면 회심에 강타음을 붙인다(선택).

조조전 스프라이트를 삼14 화면에 2D로 덧그리는 방식은 로드맵 2단계(중립군 형상)와 함께 판단한다. 통합모드 2D(SAN14_2D v27) 형식으로 변환하는 경로는 [research/cao_cao_den/README.md](../research/cao_cao_den/README.md) 3-1절. 그 실행부에는 이동·공격 동작만 있어 막기 동작은 넣을 수 없다. 배포 시 KOEI·신조조전 자산 크레딧/허가 문제가 있다.

## 6. 남은 결정

1. 막기 효과: 완전 무효(1명) vs 50% 감소.
2. 반격(피격 측의 되받아치기)에도 적용할지. `+0x22`가 반격분인지 0단계에서 확인.

## 7. 단계

- **0단계 (진단, 한 빌드에 묶음):** 처리기에서 `output+0x20/+0x22/+0x24`, 공격·피격 종류, 주장 무력·사기, 호출 직전·직후 `army[0x148]+0x580+0x14` 값을 `log_event`로 남긴다 → `+0x22`의 의미, 반응 단계 값 범위, 하루 호출 수. REA로 `+0x14` 소비 함수와 글자 팝업 후보를 같은 차례에 찾는다. `1749A0`의 다른 호출자 유무를 전체 분석본에서 확인.
- **1단계:** 막기·회심 효과 + 연출 1순위(가능하면) + 설정 + 설치기 3곳 + 모의 검사(확률 경계, 0/1명 처리, u16 상한, 비부대 대상 무시, 설정 OFF 무변경).
- **2단계:** 글자 연출·전황 메시지, 조조전 특기(치명방어 등)에 대응하는 삼14 개성 연결.

### 2026-11-08 실제 10일 교전 측정 (하후연 114 vs 여포 987)

`SAN14_AITactics.log` 04:36:24~04:36:31, 게임일 70080~70089:

| 항목 | 값 |
|---|---:|
| 일반 공격 | 60회 (양쪽 30회) |
| 자연 발동(막기/회심) | 5회 (회심 3, 막기 2) |
| 기존 5회 상태로 처리된 공격 | 17회 |
| 막기/회심으로 처리된 공격 합계 | 22/60 = **36.7%** |

5%는 공격 1회당이고, 공격마다 회심 굴림 1회 + 피격 막기 굴림 1회가 있어 10일에 120회 굴림이 된다. 기대 자연 발동은 6회, 실제 5회로 확률 자체는 5%에 가깝다. **체감 36.7%는 5회 지속이 만든 배율**이다.

측정값을 넣은 조절식(작은 p 근사):
- 10일당 자연 발동 `T`회를 원하면 `p ≈ T / (2 × 60) = T / 120`.
- 전체 공격 중 막기/회심 비율 `C`를 원하면 `p ≈ C / (2 × kCharges)`.
- 예: `T=1` → p≈0.83%, 커버리지≈8.3%. `T=2` → p≈1.67%, 커버리지≈16.7%. `C=10%`(5회 유지) → p≈1%.

이제 목표를 “10일당 몇 회”로 할지 “전체 공격의 몇 %”로 할지 정하면 위 식으로 바로 맞출 수 있다.

### 2026-11-08 적용: 8회 지속·28% 목표·능력치 분리

사용자 결정:
- 막기·회심 지속을 5회 → **8회**.
- 36.7% → **28%**가 되도록 기본 확률을 5% → **2.3%**로 낮춤. 60공격·120굴림 모의에서 p=2.3%·8회 지속은 약 28% 커버리지, 10일당 2.4회 발동이었다.
- **막기**는 `피격 지력 − 공격 지력`, `피격 사기 − 공격 사기`에 의존.
- **회심**은 `공격 무력 − 피격 무력`, `공격 사기 − 피격 사기`에 의존.
- 계산식(per mille): 막기 `clamp(23 + (iv-ia) + (mv-ma)/2, 3, 30)`, 회심 `clamp(23 + (wa-wv) + (ma-mv)/2, 3, 30)`.
- 훅 위치·피해 처리·연출·8회 상태 만료(마지막 교전일+1)는 그대로.

원작 삼국지14에는 조조전식 막기/회심이 없으므로 「원작 빈도」는 존재하지 않는다. 비교 기준은 조조전의 공격 1회 판정(지속 없음)이며, 그쪽에 맞추려면 `kCharges=1`이 가장 가깝다.
