# 삼국지14 CE KO — AI 전술 모드 기능 상세

이 문서는 모드가 **원작 게임의 어떤 코드를 어떻게 바꾸는지**, 그리고 **그 변경으로 무엇을 바꾸려는지**를 기능별로 정리한 설명서입니다. 주소는 모두 원작 실행 파일 `SAN14CE_KO.exe`(SHA-256 `87ed4e46…2d6a`) 기준 RVA입니다. 다른 버전의 EXE에서는 모드가 바이트 검사에 실패해 해당 기능을 연결하지 않습니다.

- 대상 버전: v12.22-rc2 (2026-10-23, 시험 배포). 기존 근거에 마지막 절의 신규 연결을 추가했다.
- 원작 EXE 파일은 바꾸지 않습니다. 실행 중 메모리에서만 연결하며, 해제는 설치 관리자의 원본 복구를 사용합니다. 이미 바뀐 게임 진행 결과와 숙련 설정 저장 값까지 되돌리는 뜻은 아닙니다.
- 저장 파일의 기본 컨테이너 형식은 원작과 같습니다. 숙련 공방 설정 값이 바뀐 저장은 기능을 켠 채 이어 하는 것을 전제로 합니다. 모드 전용 정보(논공 친애, 명품창고)는 별도 보조 파일에 저장합니다.

### 원작 코드를 바꾸는 방식 (5가지)

1. **가상함수표 슬롯 교체**: 원작 클래스 vtable의 함수 포인터 하나를 모드 함수로 바꿉니다. 모드 함수는 대부분 원작 함수를 그대로 호출한 뒤, 앞뒤로 필요한 판단만 더합니다. 교체 전에 슬롯이 원작 값인지 확인하고, 다르면 연결하지 않습니다.
2. **호출 지점 교체(CALL/JMP 링크)**: 원작 코드의 `CALL`/`JMP` 한 개를 모드 함수로 돌립니다. 16바이트 블록을 원자적으로 바꾸고, 원래 바이트와 다르면 연결하지 않습니다.
3. **함수 입구 가로채기**: 원작 함수의 첫 명령 몇 바이트를 점프로 바꾸고, 원래 명령은 별도 공간(relay)에 보존해 원작 함수를 계속 호출할 수 있게 합니다.
4. **상수 바이트 변경**: 능력치 상한처럼 원작의 비교 상수만 바꿉니다(예: `CMP 100` → `CMP 200`).
5. **표시 전용 UI 객체 추가**: 원작 UI 클래스로 초상화·글자를 만들어 원작 이름표의 자식으로 붙입니다. 게임 데이터는 쓰지 않습니다.

공통 원칙:
- 모든 원작 함수 호출은 **원작이 자기 UI/AI 스레드에서 부른 흐름 안에서만** 실행합니다. 새 스레드에서 게임 함수를 부르거나 외부 프로그램이 게임 메모리를 쓰지 않습니다.
- 연결 전에 대상 바이트·슬롯을 모두 검사합니다. 공통 필수 연결 검사가 다르면 해당 모듈 연결을 중단할 수 있으며, 선택 기능의 검사가 다르면 그 기능만 건너뛰는 경로도 있습니다.
- 기능 하나가 실패하면 이미 연결한 부분을 원래대로 되돌립니다.

## 2. 전투 AI 교정 — `SAN14_CombatAI.dll` (`[groups] combat`)

컴퓨터 운용 부대의 군사 판단을 고칩니다. 원작 요격·원군 경로도 유지하며, 플레이어 위임 군단의 출진에는 별도 방침 제한이 있습니다.

### 2.1 원작 AI의 구조 (모드 이해를 위한 배경)

원작 AI는 **행동 트리**로 판단합니다.
- **군단 판단표**: 출진할지, 어떤 목적으로 출진할지 정합니다. 출진 노드가 부대를 만들고, 그 부대들이 속한 **군세**(Troops)의 종류(군세+14)와 목표(군세+16)를 기록합니다.
- **군세 판단표**: 매 판단마다 군세 종류에 따라 소속 부대의 명령을 다시 씁니다(성 공격 8·9·10·22, 지역 점령 13·14, 요격 1, 임무 해제 0 등).
- **부대 판단표**: 개별 부대의 화계·보급·주변 점령·병참 절단을 판단합니다.

## 3. 게임성 — `SAN14_Convenience.dll`

### 3.1 지원·내정 군단 출진 제한 (`[combat] district_intercept_block`, 전투 DLL 불필요)

| 원작 지점 | 원작 역할 | 모드 변경 |
|---|---|---|
| 입구 `1EC890` | 모든 출진 명령 실행기. 행동 트리의 출진 노드(요격 34F10, 자동 방어 출진 2C230, 지역 점령·확보, 성 공격, 수송)가 모두 여기로 옵니다. | 명령을 실행하기 전에 출진 무장의 군단 방침과 명령 행동을 보고 막을지 판정합니다. 전투 DLL이 있으면 그 DLL의 기존 훅 안에서, 없으면 편의 DLL이 같은 입구를 직접 연결해서 판정합니다(두 DLL이 동시에 연결하지 않음). |

- **원작의 문제**: 원작 군단 판단표는 플레이어 세력 군단을 방침과 상관없이 공통 분기로 보냅니다. 방침을 보는 곳은 성 공격 허용 비트뿐이라, 지원·내정 방침으로 위임한 군단도 요격군·방어 출진·지역 점령 출진을 내보냅니다.
- **지원** 방침: 수송 출진(행동 2·3)만 허용합니다.
- **내정** 방침: 요격·지역 이동/점령·공격 출진(행동 1·4·5·7·14)을 막고, 수송·건설은 허용합니다.
- **그대로 두는 것**: 컴퓨터 세력, 플레이어 직할 1군단, 공격 방침, 플레이어 직접 명령, 이미 출전한 부대.
- 막힌 출진은 원작의 "출진 실패" 처리로 넘어갑니다.
- **수송 출발지 보완(v12.19)**: 원작은 반경 15칸 안에 적 부대가 있는 거점을 수송 출발지에서 뺍니다(조건84 = `AEE60`, 주변 부대를 모아 적대 세력인지 확인). 요격이 금지된 지원·내정 군단은 적을 치우지 못해 수송이 영영 나가지 않으므로, 이 군단들의 거점에 한해 "거점·15칸" 검사만 참으로 처리합니다. 조건 분배 함수의 해당 분기 CALL 한 곳(`C2F73`)만 바꾸며, 반경 10칸·칸·관문 검사와 다른 군단은 원작 그대로입니다.
- 위임방침은 군단 데이터 +0x17 바이트입니다(내정 4, 지원 5). 실행 중인 게임에서 방침을 바꿔 가며 읽기 전용으로 비교해 확인했습니다(`tools/corps_policy_probe.py`). 소속 군단은 무장 +0xE0 → 군단 표(world+0xE0D0)로 찾습니다.

## 7. 바꾸지 않는 것

- 원작 EXE 파일과 저장 컨테이너의 기본 형식(모드 보조 파일·숙련 설정 값과 구분). ScreenLayout 선택 항목은 설치·복구 시 병합 변경합니다.
- 직할 1군단의 출진 제한 제외·수동 임명 비용. 단, 1군단 자동 내정을 켜면 직접 고른 개발 항목도 바뀝니다. 위임 무장의 수동 출진 모든 경로를 예외 처리한 것으로 보장하지 않습니다.
- 실행 중 외부 프로그램이 게임 메모리를 쓰거나 게임 함수를 원격 호출하는 일

## 8. 검증 수준

각 기능은 원작 EXE 바이트·슬롯 대조와 모의(fixture) 검사를 통과한 뒤 배포합니다. 모의 검사는 실제 게임 화면·장기 플레이를 대신하지 못하므로, 실제 게임에서의 동작 확인은 버전별 기록(`development/CURRENT.md`)에 따로 적습니다. 배포 파일은 코드 서명되지 않았습니다.


## 9. 소스 재대조에서 보완한 동작

DLL 이름이나 설치기 항목 제목만으로 놓치기 쉬운 변경이다. 일반 설명은 [모드 전체 설명](../README.md)에 반영했다.

| 함수 | 현재 코드에서 확인한 변화 |
|---|---|
