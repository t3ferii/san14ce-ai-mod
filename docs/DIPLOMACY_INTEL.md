# 외교 군정 초과 투입·마지막 대응

2026-10-26 사용자 요청. 이번 작업은 사용자 명시 승인으로 Codex가 단독 설계·구현·검증한다.
소유자는 SAN14_Convenience.dll이며 게임성 탭의 두 독립 항목으로 관리한다.

- `[diplomacy] diplomacy_overinvest`: 컴퓨터가 시작한 친선(4), 동맹(5), 포로반환(8), 공격요청(9)의 플레이어 응답에서 보유 군정까지 투입. 100%를 넘긴 방어분도 계산에 남긴다.
- `[diplomacy] diplomacy_counterturn`: 컴퓨터의 마지막 응답 후 플레이어에게 추가 입력을 한 번 준다. 추가 입력을 확정하면 컴퓨터가 다시 투입하지 않고 원작 결과 적용 단계로 간다.
- 설치기 기본 ON, DLL에서 설정 누락 시 OFF. 편의 묶음에 종속. 재시작 시 적용.
- 플레이어가 시작한 교섭, 항복, 컴퓨터끼리의 교섭, 원작의 고정 결과는 제외한다.
- 게이지는 원작의 0~100 범위다. 방어분 초과 시 플레이어 쪽 수치는 100%를 넘겨 표시한다. 실제 최종 성공 확률은 0~100으로 제한한다. 초과분은 확률 자체가 아니라 상대의 추가 투입을 흡수하는 방어 여유다.
- 군정 소모는 원작 응답 함수가 한다. 추가 대응을 위해 첫 투입을 환불하거나 다시 차감하지 않는다. 영구 세이브 필드·새 보조 저장 파일은 없다.

## 원작 근거

- 추가 대응은 위 판정 CALL만 잠시 보류한다. 이때 부모 layout +190 `805010(layout,event)`의 종료 이벤트 `7FFFFFFD`만 삼킨다. 원작 함수가 돌아오면 같은 window의 8단계를 다시 연다. 두 번째 11단계에서는 AI를 실행하지 않고 저장해 둔 판정 인자와 최신 점수로 한 번 판정한다. 원작 12/13단계가 조건과 포로 등 실제 결과를 적용한다.
- `322B30`은 점수 계산, `3228F0`은 한계 도달에 필요한 군정량이다. Ghidra가 SSE 연산을 누락한 의사코드를 내므로 계수와 순서는 asm으로 확인했다. 4자리 반올림 후 정수 절삭을 보존하고, 새로 노출된 큰 투입량에서는 원작의 중간 int32 오버플로를 피한다.
- CPU의 `804770`은 확률을 0~100으로 제한한다. 원작 AI는 제한된 확률로 판단하고, 그 판단이 만든 점수 변화만 원래 방어 여유에 합친다.

## 검사와 실게임 확인 경계

`tools/check_feature.ps1 -Feature diplomacy-intel`은 정적 바이트·호출·화면 번호와 실제 어댑터를 포함한 합성 UI fixture를 검사한다. 계산 반올림, 큰 투입량, 초과분, 양쪽 설정, 원작 위임, 입력 재개, RNG 판정 지연, 두 번째 AI 실행 방지, 협상 수명 초기화가 대상이다.
필수 분리 검사 `-Feature dll-split -Build`, 진단판 `tools/build_split.ps1 -RuntimeDiagnostics`, 설치기 `tools/build_installer.ps1`을 별도로 수행한다.

실게임에서 사용자가 확인할 부분: 컴퓨터가 제안한 각 교섭의 숫자 입력/슬라이더, 100% 초과 표시의 폭, 첫 투입 후 잔액, 컴퓨터 응답 후 입력 재개, 추가 투입 후 잔액과 최종 결과, 취소·재진입. 모의 검사가 이 화면 동작·장기 안정성을 증명하지 않는다. Computer Use는 사용하지 않는다.
