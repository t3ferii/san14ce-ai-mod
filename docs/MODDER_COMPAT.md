# 다른 모더용 호환 지침 (이 저장소를 AI에게 맡길 때)

이 문서는 다른 모더가 두 가지 일을 할 때 읽는다. 사람이 읽어도 되지만, 주로 그 모더가 이 저장소를 맡기는 AI가 읽는다고 보고 썼다.

- **A. 함께 쓰기**: 자기 모드를 이 모드(삼14CE AI교정 모드)와 같이 설치해도 깨지지 않게 만든다.
- **B. 고치기**: 이 소스를 fork해서 고치거나 새 기능을 얹는다.

이 모드는 디스크의 게임 EXE를 고치지 않는다. 게임이 실행된 뒤 메모리에서 원작 함수에 훅을 걸어 동작한다. 지원하는 게임판은 `src/game_addresses.h` 주소표와 `src/native_profile.h`가 기준으로 삼는 Steam 현재판이다. 다른 빌드에서 쓰려면 주소·바이트·호출 규약을 다시 확인해야 한다.

## 0. AI에게 줄 첫 지시 (복사해서 쓰기)

```text
이 저장소는 삼국지14 PK(SAN14CE_KO.exe)용 AI교정 모드 소스다.
먼저 docs 폴더의 MODDER_COMPAT.md, AI_EDITING.md, FEATURE_RULES.md를 읽고 따른다.
목표: <원하는 게임 동작. 유지해야 할 기존 동작도 적는다>
수정해도 되는 파일: <목록. 그 밖의 파일이 필요하면 고치지 말고 보고>
지원 게임판: <SAN14CE_KO.exe 버전 또는 해시>
금지: 실행 중인 게임 메모리에 쓰기·원격 호출, 원래 바이트 가드 삭제·약화, 실패한 검사의 기대값을 낮춰 통과시키기.
보고: 바꾼 파일, 건드린 원작 자리(주소표 id), 실행한 검사와 결과, 실행하지 못한 검사와 이유, 실게임에서 확인하지 않은 범위.
```

## 1. 이 모드의 구조

| 파일 (게임 폴더) | 역할 |
|---|---|
| `dinput8.dll` | 로더. 입력 호출은 앞 차례 제공자나 System32로 넘기고, 아래 모듈만 불러온다 |
| `SAN14_Layout.dll` | 훅 관리자와 화면(UI) 훅. 모든 모듈의 훅 등록을 받아 한 번에 건다 |
| `SAN14_CombatAI.dll` | 컴퓨터 AI 판단 |
| `SAN14_Convenience.dll` | 그 밖의 기능. 훅 가드와 게시를 조정한다 |
| `SAN14_CCZ.dll`, `SAN14_ModPack.dll` | 조조전 탭 기능, 다른 모더 패치의 이식. 편의 모듈이 불러온다 |
| `AI_TacticsMod\기능설정.ini` | 모든 설정. 키 목록은 `docs/FEATURE_SWITCHES.md`, `development/installer_map.json` |
| `SAN14_AITactics.log`, `SAN14_CombatAI.log` | 진단판에서만 남는 로그. 배포판에는 진단 코드가 없다 |

불러오는 순서는 이렇다(`src/module_loader.cpp`). 게임이 `dinput8.dll`을 불러오면 로더가 별도 스레드를 띄운다. 그 스레드가 Layout → 전투 → 편의 모듈 순으로 불러오고, 편의 모듈이 조조전·ModPack 모듈을 불러온다. 모든 모듈이 훅을 등록한 뒤 Layout이 한 번에 게시한다. `기능설정.ini`의 `[groups]` 키 `combat`·`convenience`·`performance`가 모두 0이면 아무것도 불러오지 않는다.

기능 하나는 모듈 하나다. 모듈마다 매니페스트(`development/modules/<id>/module.json`)가 있고, 여기에 소유 파일·설정 키·훅 자리·검사 경로가 적혀 있다. 전체 표는 `docs/MODULES.md`다.

## 2. A. 함께 쓰기: 다른 모드 쪽에서 지킬 것

### 2-1. `dinput8.dll` 자리

이 모드의 로더 이름이 `dinput8.dll`이다(`src/input_proxy.cpp`).

- 게임 폴더에 `SAN14_AI_PreviousInput.dll`이 있으면 로더는 `DirectInput8Create`를 그 파일로 넘긴다. 없으면 System32의 `dinput8.dll`로 넘긴다.
- 우리 설치기(`distribution/Manage.ps1`)는 설치할 때 이미 있던 `dinput8.dll`을 `SAN14_AI_PreviousInput.dll`로 옮기고 두 파일의 해시를 기록한다. 해제할 때 원래 이름으로 되돌린다. 갱신·해제 때 해시가 기록과 다르면 사용자 파일을 지키려고 멈춘다.
- 가장 간단한 방법은 `dxgi.dll`, `version.dll`, `xinput1_3.dll`처럼 다른 프록시 이름을 쓰는 것이다. 파일이 겹치지 않는다.
- 당신 모드도 `dinput8.dll` 프록시라면:
  - **당신 모드를 먼저 설치**한다. 그러면 우리 설치기가 당신 로더를 앞 차례 자리로 옮기고, 우리 로더가 계속 불러 준다.
  - 우리 모드를 설치한 뒤에는 `dinput8.dll`이나 `SAN14_AI_PreviousInput.dll`을 직접 바꾸지 않는다. 우리 설치기의 갱신·해제가 멈춘다. 당신 로더를 갱신하려면 우리 모드 해제 → 당신 로더 갱신 → 우리 모드 다시 설치 순서로 안내한다.
  - 당신 로더가 앞에 서서 우리 `dinput8.dll`을 다음 차례로 부르는 반대 순서는 확인하지 않았다(미검증).
- 서로를 부르는 순환은 우리 쪽에서 막는다. 같은 호출 안에서 우리 로더에 다시 들어오면 System32로 빠진다.

### 2-2. 같은 원작 자리를 고칠 때

이 모드는 훅과 바이트 패치를 걸기 전에 **원래 바이트(또는 원래 vtable 값)를 확인**한다. 체인을 허용한 일부 자리만 다른 모듈이 먼저 건 값을 받아 체인한다(아래 「체인하려는 경우」).

- **당신 모드가 먼저 그 자리를 고친 경우**: 체인 자리가 아니면 우리 쪽은 그 기능 하나만 끄고 나머지는 계속 동작한다. 진단판 로그에 `split_disable` 또는 Layout 거절 이유가 남는다. 게임은 깨지지 않지만 우리 기능 하나가 조용히 꺼질 수 있다.
- **우리가 먼저 고친 자리를 당신이 고치는 경우**: 쓰기 전에 원래 바이트를 확인하고, 다르면 건너뛰기를 권한다. 무조건 덮어쓰면 우리 훅의 중계 코드가 잘려 게임이 튕길 수 있다.
- **체인하려는 경우**: vtable 슬롯이나 `call` 자리를 덮어쓰기 전에 현재 값을 읽어 "다음"으로 저장한다. 그리고 당신 함수에서 원작 주소 대신 그 값을 부른다. 우리 Layout도 체인을 허용하는 자리(`LAYOUT_CHAIN_OK`)에서는 다른 모듈이 먼저 건 값을 "다음"으로 받는다.
- **같은 16바이트 블록**: 서로 다른 자리라도 같은 16바이트 블록 안의 패치는 피한다. Layout을 거치는 코드 패치(`hook_block`·`hook_span`)는 16바이트 블록 단위 원자 교체(CMPXCHG16B)로 쓰므로, 블록이 겹치면 한쪽이 실패할 수 있다.
- **우리 훅 자리 찾기**:
  - `development/hook_sites.json`: 훅 자리 목록. 주소표 id 기준이다.
  - 모듈 매니페스트의 `hooks`·`hook_owners`.
  - 빌드 뒤 `tools/hook_map.py`가 만드는 `build/development/hook_map.json`.
  - 현재 빌드의 실제 RVA는 `src/game_addresses.h` 주소표에서 본다.

### 2-3. `SAN14_Layout.dll` API (선택)

`SAN14LayoutGetApi(1)`가 `San14LayoutApiV1` 표를 돌려준다(`src/layout_api.h`). 표의 `size`로 뒤에 덧붙은 항목이 있는지 확인한다.

- 훅 등록: `hook_vtable`, `hook_call`, `hook_bytes` 등.
- 자리 주인 확인: `slot_owner`.
- 화면 생성·소멸 알림: `on_layout_built`, `on_layout_destroyed`.
- 그리기·입력 구독: `overlay_subscribe`, `wndproc_subscribe`.

이 API로 훅을 걸면 같은 자리의 소유·체인·되돌리기를 우리 훅과 같은 표에서 관리한다. 다만 **외부 모드용 안정 ABI로 검증한 적은 없다**. 쓰기 전에 `src/layout_main.cpp`에서 두 가지를 확인한다. 하나는 등록 시점이다(게시 전후). 다른 하나는 vtable 교체를 우리 모듈에만 허용하는 표시(`LAYOUT_NEED_WHITELIST`)다. 쓰기로 했으면 우리에게 알려 준다(5절).

### 2-4. 설정·저장·로그

- 우리 설정 파일(`AI_TacticsMod\기능설정.ini`)에 당신 키를 넣지 않는다. 사용자에게 우리 기능을 꺼 달라고 안내할 때는 해당 키를 0으로 하라고 적는다. 키 목록은 `docs/FEATURE_SWITCHES.md`에 있다. 끈 기능은 원작 동작으로 돌아간다.
- 우리는 원작 세이브 형식을 바꾸지 않는다. 기능 자료는 세이브 옆 별도 파일(사이드카, `src/save_host.h`)에 둔다. 당신 모드가 원작 세이브 구조를 바꾸면 우리 저장 경로와 겹치는지 확인한다.
- 우리 로그 파일 이름(1절 표)을 쓰지 않는다.

### 2-5. 화면 자료 (`ScreenLayout.rdb`)

- 일부 기능은 디스크의 화면 자료(`0002/ScreenLayout.rdb`와 참조 bank)에 모드용 bank 24~31을 더하고 참조를 바꾼다. 우리 설치기가 설치 전 원본을 기준으로 바꾸고, 해제할 때 되돌린다. 다른 모드가 바꾼 참조·공유 bank는 보존하는 것이 우리 기준이다(`docs/UI_RESOURCE_LIFECYCLE.md`).
- 당신 모드도 화면 자료를 고친다면 bank 24~31을 쓰지 않는다. 우리 설치 뒤에 이 파일을 통째로 덮어쓰지 않는다. 덮어쓰면 우리 화면 자료가 사라지고, 해제 때 되돌릴 기준도 어긋난다.

### 2-6. 호환을 매니페스트로 확인하기

- 당신 모드의 훅 자리를 매니페스트 형식으로 적는다. 형식은 `docs/MOD_MANAGER_DESIGN.md` 2절의 schema 1이고, 소스가 없는 모드는 `hooks`에 `{"key": "GA_...", "len": 5}`로 적는다.
- 그 다음 아래 명령을 실행하면 우리 모든 모듈과 비교한다. 게임은 실행하지 않는다.

  ```powershell
  python -X utf8 tools/mod_compat.py --manifest <당신 매니페스트>.json
  ```

  비교 항목은 같은 훅 자리, 같은 16바이트 블록, 같은 원작 주소 쓰기, 설정 키, UI 자리, API 이름이다. 우리 쪽 훅 자리는 모듈 매니페스트의 `hooks`에서 읽으므로 `build/` 폴더 없이 소스만으로 된다. 우리가 훅을 건 주소표 id를 넣은 시험 매니페스트로 같은 자리 오류가 나는 것을 확인했다(2026-11-16, 소유자 작업 폴더).
- 우리 쪽 다른 모드 표(`development/foreign_hooks.json`, schema 2)는 지금 비어 있다. 당신 모드의 **현재 버전** 소스나 훅 목록이 있으면 그 기준으로 채울 수 있다. 옛 버전 기록은 쓰지 않는다.

## 3. B. 이 소스를 고칠 때 (AI가 지킬 것)

읽는 순서는 다음과 같다. 저장소 전체나 `research/`를 한꺼번에 읽지 않는다.

1. `README.md`
2. 이 문서
3. docs 폴더의 `AI_EDITING.md`: 영역별 `AI-CONTRACT` 제약(공개 저장소에 있음)
4. `docs/FEATURE_RULES.md`: 새 기능 규칙
5. `docs/MODULES.md`의 관련 행
6. 바꿀 함수와 그 호출자

핵심 규칙(자세한 내용은 FEATURE_RULES):

1. 원작 주소는 주소표 id(`GA(GA_...)`)로만 쓴다. 기능 코드에 RVA 숫자를 쓰지 않는다.
2. 새 훅·패치마다 원래 바이트 가드를 두고, 맞지 않으면 그 기능만 끈다(`split_disable`). 전체 `.text` CRC를 동작 조건으로 쓰지 않는다.
3. 스위치를 끄거나 DLL이 없으면 원작 동작 또는 그 전에 깔린 모드의 동작이어야 한다. 기능이 만든 UI도 함께 사라진다.
4. 원작 함수는 게임의 UI·AI 스레드에서만 부른다. 외부 프로세스에서 게임 메모리에 쓰거나 함수를 원격 호출하지 않는다.
5. 게임 효과는 원작 함수에 훅을 걸어 결과를 바꾸거나 게임 스레드에서 원작 함수를 불러서 만든다. 게임 메모리 값을 직접 고쳐 효과를 내지 않는다.
6. 컴퓨터 AI 규칙은 플레이어가 직접 지휘하는 군단과 위임 군단에 적용하지 않는다.
7. 코드의 `AI-CONTRACT` 주석은 수정의 전제조건이다. 지우지 말고 바뀐 내용에 맞춰 고친다.
8. 모듈 경계를 지킨다. `python -X utf8 tools/feature_deps.py --check`가 다른 모듈 함수 직접 호출, 다른 DLL 심볼 사용, 다른 모듈 스위치 직접 읽기를 막는다.
9. 검사가 실패하면 검사를 고치거나 코드를 고친다. 기대값을 낮추거나 "원래 실패하던 것"으로 넘기지 않는다.
10. 구조체 오프셋·함수 의미는 바이트와 호출자로 확인한다. 디컴파일러의 의사코드와 함수 이름의 비슷함은 가설일 뿐이다.

검사 명령:

| 목적 | 명령 |
|---|---|
| 이 저장소만으로 되는 빌드 확인 | `tools/build_public_smoke.ps1` (`-Combat`, `-Ccz` 옵션) |
| 바꾼 기능의 검사 경로 | `tools/check_feature.ps1 -Feature <기능> -List` 다음 그 경로 실행 |
| 매니페스트·모듈 경계 | `python -X utf8 tools/run_checks.py --routes manifest,module-manifests,feature-deps --keep-going` |
| 훅 자리 지도 | `python -X utf8 tools/run_checks.py --routes hook-map` |

공개 저장소만으로 확인한 명령은 `build_public_smoke.ps1`이다. 나머지 명령은 소유자 작업 폴더에서 확인했다. 전체 split 빌드와 원작 바이트 검사에는 이 저장소에 없는 원작 자료·외부 payload가 필요하다(공개 저장소 docs 폴더의 `SOURCE_DEPENDENCIES.md`). 자료가 없어 못 한 검사는 통과로 적지 않고 "실행 못 함"으로 적는다. 모의 검사(fixture) 통과는 실게임 확인이 아니다.

## 4. 배포할 때

- 변경본은 README·설치기에 이름과 버전을 우리 것과 구별해 적는다. 사용자가 어느 판을 깔았는지 알 수 있어야 한다.
- 수정·재배포 범위는 `LICENSE`를 따른다. 외부 payload와 다른 모더 자산의 출처·조건은 `THIRD_PARTY.md`와 `docs/CREDITS.md`에 있다. 우리가 다른 모더에게서 가져온 부분의 크레딧을 지우지 않는다.
- 원작 게임 파일, 게임 코드 덤프, 사용자 세이브·로그는 배포하지 않는다.
