## 1. 이미 있는 기반

- 편의 DLL의 D3D11 훅: `unified_overlay`(Present/Present1, WndProc), `gpu_profile`(CreateSwapChain → Present, 즉시 컨텍스트의 OMSetRenderTargets·Draw 7종) — [GPU_RENDERING.md](GPU_RENDERING.md). 렌더타깃 전환마다 단계를 나누는 코드가 이미 있다.

## 2. 구조 (권장안)

| 단계 | 내용 | 스레드 |
|---|---|---|
| 수집 | 원래 UI/AI 콜백에서 대상 부대(조조전 중립군)의 id·칸 좌표·방향·이동/공격 상태·진영을 복사해 게시 | 게임 콜백 |
| 위치 | 칸 → 월드 좌표: 원작 격자 함수/값으로 계산(REA 필요). 땅 높이는 원작 높이 조회 | 게임 콜백 |
| 숨김 | 대상 부대의 원래 3D 모형 DrawIndexed만 건너뛴다. 그리기의 월드 행렬 이동값을 게시된 부대 위치와 맞춰 식별 | 렌더 |
| 그리기 | 3D 장면이 끝나고 UI가 시작되는 렌더타깃 전환 직전에, 장면 깊이 버퍼로 깊이 검사하며 빌보드 사각형을 그린다. 카메라 view/proj는 원작 카메라 객체 또는 VS 상수 버퍼에서 읽기만 | 렌더 |
| 연출 | 막기(`Unit_spc` 0~2 방어), 피격(3), 회심(공격 프레임 + 섬광)을 전투 DLL이 게시한 사건으로 재생 | 렌더 |

- 렌더 스레드는 복사된 값과 GPU 리소스만 쓴다. 게임 함수 호출·게임 메모리 쓰기 없음(기존 규칙).
- 소유: 렌더·수집은 **편의 DLL**. 막기·회심 사건은 전투 DLL이 공용 `log_event`/게시 구조로 넘긴다. 새 DLL·d3d11 프록시 없음(세 DLL 규칙).
- 안개: 원작 안개 상태로 보이지 않는 부대는 그리지 않는다.

대안(2D 모드 방식): 부대 모형 DrawIndexed를 가로채 그 상수 버퍼 행렬로 같은 자리에 그림을 그린다. 카메라 조사가 필요 없지만, 그리기 ↔ 부대 대응을 모형 크기로 추정해야 해서 대상 부대만 골라내기 어렵다.

## 3. 그림 자산과 배포

- 사용자 결정(2026-10-31): 조조전 자산은 저작권 제약이 없는 상태이므로 **추출한 그림을 모드에 넣는다.** 크레딧은 [assets/ccz/README.md](../assets/ccz/README.md)와 배포 크레딧 규칙을 따른다.
- 자산: `assets/ccz/ccz_units.bin`(CCZU v2 = 0-연속 RLE, 병종 240칸, 7.2MB, 원본 바이트 일치 검사). DLL에 zlib가 없어 v1(zlib)에서 바꿨다. 색 번호 그대로 저장해 렌더러가 셰이더 팔레트로 진영색(아군·적군·중립)을 입힌다.
- 팀색: 녹색·청록 단계(`ccz_units.json`의 `team_indices`)를 진영색으로 치환. 원작 치환표는 `Ekd5.exe`에서 찾아야 한다(현재는 색상환 회전 근사).
- 설치 묶음에 넣는 일(`build_share.py`·설치기)은 공용 파일이라 렌더러 1단계와 함께 한다. 현재 `build_share.py`는 manifest `assets`가 있으면 멈추므로 그 규칙도 같이 바꿔야 한다(총괄 세션 확인).

## 4. 조사 목록 (REA 한 차례 + 진단 빌드 한 번에 묶음)
