# 원작 UI 수정 실패 기록과 재사용할 해결 방식

2026-11-03 조조전 설정·외교 마지막 대응 작업 기록. 목적은 같은 실패를 다른 화면에서 반복하지 않는 것이다. **UI를 고칠 때 먼저 증상에 해당하는 항목만 읽는다.** 전체 문서·전체 역분석을 매번 다시 읽을 필요는 없다.

이 문서의 주소는 당시 분석한 CE 빌드 기준 RVA다. 다른 EXE에 그대로 적용하지 말고 기존 함수 가드·호출자·ABI를 확인한다. 기준 분석본은 `build/ui_native_analysis/editor83_plain/game.exe.unpacked.exe`, 분석 캐시는 `research/decomp_cache/1fbe6be7466a6646/`이다. 실제 설치 버전은 [CURRENT](../development/CURRENT.md)를 따른다.

## 증상별 먼저 볼 곳

UI 자료를 바꾸거나 OFF/해제 후 버튼이 남으면 [UI 리소스 복원 기준](UI_RESOURCE_LIFECYCLE.md)을 먼저 확인한다. DLL OFF와 디스크 리소스 복원은 별개다.

**조조전 OFF 또는 모드 해제 후에도 부대 UI 위치가 남는 경우:** [리소스 색인 복원 기록](CCZ_LAYOUT_SWITCH.md)을 먼저 확인한다. DLL 훅을 고치는 문제가 아니라 설치기의 설정별 화면 패치와 오염된 원본 참조를 복구하는 문제였다.

| 증상 | 이 세션에서 실패한 접근 / 놓친 점 | 재사용할 해결 방식 |
|---|---|---|
| 버튼은 클릭되는데 그림이 안 보임 | 등록·좌표·enabled만 확인. 표시 비트와 상속 alpha는 별개였다 | 표시 비트·부모 표시 캐시·자기 alpha·부모 alpha를 함께 확인 (§1) |
| 로고 사이에 첫 메뉴가 끼어 보임 | 메뉴 생성 완료와 실제 표시 단계가 같다고 취급 | 원작 메뉴 전환 단계에 맞춰 행만 표시 (§1) |
| 원형 결정·뒤로가 계속 사라짐 | 생성 후 프레임에서 복원하는 시도만으로 해결되지 않음 | 객체 생성 직후, 모달 큐 등록 전에 footer 구성 (§2) |
| 목록 전체가 회색이고 다른 병종 선택 불가 | 원형 버튼을 얻으려고 목록을 다중 선택/최대 1개로 변경 | 단일 선택 유지, footer를 별도로 구성 (§3) |
| 선택한 병종이 재진입하면 초기화 | 하위 선택 확정과 전체 설정 저장을 혼동 | Gallery의 결정과 Root의 전체 저장을 분리 (§4) |
| 목록·스크롤이 테두리 밖으로 나옴 | 바깥 CUI 크기만 변경 | 실제 clipping drawable·스크롤 내부 길이도 갱신 (§5) |
| 조형 위에 빈 무장 초상화가 뜸 | 무장 선택 UI의 기본 hover 콜백을 그대로 사용 | 생성 전 config에서 빈 hover 모드 지정 (§3) |
| 외교 추가 투입 때 결정 버튼·인물이 퇴장 | 판정만 보류해도 원작 UI 정리 경로는 계속 실행 | UI 퇴장 분기 보류와 입력 단계 복구를 함께 처리 (§6) |
| 래퍼 로그에 판정/RNG가 없음 | 입력 스레드만 기록 대상으로 인정 | 원래 함수 호출 범위의 TLS 진단 스코프 인정 (§7) |

## 1. 첫 메뉴 버튼: 등록·표시·alpha·전환은 별개

현재 구현: [native_ccz_title.inl](../src/native_ccz_title.inl).

- 원작 마지막 메뉴 행 생성 CALL `4E83F3 → 866230(root,id,pane,order)`을 감싼다. **원작 호출을 먼저 완료**하고 초기화 중 해당 root·`id=32`일 때만 추가한다. 같은 초기화의 중복 추가를 막되, 새 title/root에서는 다시 만들 수 있어야 한다.
- 클릭 가능하다는 것은 그리기 성공의 증거가 아니다. 이전 `0xA` 마스크는 표시 bit 0을 누락했다. 현재 `sync()`는 원작 행의 `0xB` 비트를 따르고 `873370`으로 자식의 상속 표시 캐시도 무효화한다.
- 소스에 남은 당시 실게임 추적: 원작 row32 alpha=255, 추가 row37 alpha=0. flags=7·유효한 렌더 노드만으로는 부족했다. 추가 행에는 원작의 9번째 행 alpha 애니메이션이 없으므로 `873450` 원작 setter로 원작 행의 alpha를 따라간다.
- 현재 로고/로딩 단계는 phase<12, 메뉴 전환은 phase12부터다. `intro_visibility()`는 메뉴 행만 억제하며 title root·로고 레이어를 숨기지 않는다. 이 숫자는 해당 빌드의 상태 기계 근거 없이 다른 화면에 복사하지 않는다.
- 원작 8개 메뉴 위치는 유지하고 조조전 버튼만 우측 하단에 둔다.
- 초기 클릭 종료 현상은 여러 차례 사용자에게 재현됐다. **이 문서에서는 그 모든 종료의 단일 원인을 확정하지 않는다.** 현재 성공 경로의 생성/등록/콜백 ABI를 보존하며, 다시 종료되면 §7의 호출 래퍼로 마지막 완료 호출부터 좁힌다.

## 2. 결정·뒤로: footer를 만드는 시점

현재 구현: [native_unified_dialogs.inl](../src/native_unified_dialogs.inl)의 `show()`·`Dialog.on_created`, [native_ccz_editor.inl](../src/native_ccz_editor.inl)의 `gallery_footer()`·`root_footer()`.

성공한 순서:

```text
생성 전 config 설정
→ 원작 45B620 생성
→ 실제 object 확보
→ on_created에서 원형 footer·콜백 구성
→ 원작 45ED60 모달 큐 등록
→ 이후 frame에서는 기존 객체의 배치/미리보기만 관리
```

- `on_frame`에서 버튼을 보이게 하는 수정만 반복하지 않는다. 이번 버튼 실종은 **생성 후·큐 등록 전 초기화 지점**을 마련한 뒤 해결됐다.
- 기존 footer(`object+188`)의 원형 control 5=결정, 4=뒤로를 재사용한다. 목록 하단의 일반 행을 결정 버튼 대신 추가하면 외형·입력·위치가 원작 footer와 달라진다.
- `gallery_footer()`는 네이티브 footer 구성을 재현하고 표시/alpha 캐시를 갱신한다. 번호만 같다는 이유로 다른 화면 footer의 ABI·구조를 같다고 가정하지 않는다.
- 프레임 큐가 기존 list/page/bar를 참조할 수 있다. **프레임 처리 도중 파괴·교체·재생성하지 않는다.** `layout_existing_list()`처럼 기존 identity·소유권·delegate를 보존한다.

## 3. 목록 선택·hover·불필요한 목록 탭

- 조형 Gallery는 네이티브 **단일 선택** `config+18=1`을 유지한다. 다중 선택 mode2/max1은 이미 선택된 초기값이 있을 때 나머지 행을 잠가 회색·선택 불가로 만들었다. footer 표시를 위해 목록 모드를 바꾸지 않는다.
- `config+A0=0`: 클릭 즉시 적용/닫기를 하지 않고, 선택은 미리보기에 반영한 뒤 원형 결정으로 적용한다. 실제 생성 시 읽히므로 config를 생성 전에 설정한다.
- 불필요한 한 항목짜리 「목록」 탭은 `config+9C=0`으로 생성하지 않는다.
- 빈 무장 초상화는 기본 무장 hover 콜백에서 왔다. `config+114=1`로 원작의 빈 hover 콜백 경로(`45C5F0`)를 선택한다. **hover 제거와 행 선택 모드는 서로 다른 설정**이다. 초상화를 없애려고 선택 모드·delegate를 함께 바꾸지 않는다.
- 관련 생성 근거: `2C0CC4`, `2C0F53 → 2BF781`. 숫자는 원작 동작 근거와 함께 재사용한다.

## 4. 선택 확정과 전체 저장은 다른 작업

```text
병종 클릭 → 미리보기
Gallery 결정 → 현재 병종을 Session의 임시 설정에 적용
Root 결정 → 전체 임시 설정을 기능설정.ini에 저장
뒤로 → 해당 단계의 미확정 변경 취소
```

- 하위 병종의 결정이 보인다는 것만으로 INI 저장 성공이라고 보고하지 않는다. 전체 Root에 저장 경로가 없으면 재진입 때 초기화된다.
- Root의 원형 control5에는 기본 선택 콜백을 그대로 두지 않는다. `869BE0`으로 기존 click handler를 해제하고, 공용 `Command` functor ABI로 `1A3CB0`에 저장 콜백을 연결한다.
- 현재 `Session.save_requested=true → close(false) → root_done()에서 Save 큐` 순서를 보존한다. `close(false)`만 보고 취소로 처리하면 저장 요청을 잃는다. `root_done()`은 일반 accepted/cancel보다 저장 요청을 먼저 처리한다.
- Root의 목록 클릭은 계속 하위 화면 진입에 사용한다. 원형 저장 버튼은 현재 강조 행과 무관하게 전체 설정을 저장한다.
- 실제 저장 확인은 **변경 → 하위 결정 → Root 결정 → 닫기 → 재진입 → 값 확인**까지다. 뒤로 취소와 다른 사용자 키 보존도 구분한다. 사용자가 이 경로 해결을 확인했으며, 공개 무로그 DLL의 별도 실게임 확인까지 뜻하지 않는다.

## 5. 레이아웃: 외곽 크기와 실제 표시·클릭 영역

기준은 게임 논리 좌표 1920×1080이다. 첨부 스크린샷의 픽셀을 그대로 쓰지 않는다. 현재 배치: 목록 (80,90), 외곽 높이600, 기본 폭1000; 미리보기 (1280,90), 560×600. 다중 선택 체크박스가 실제 있는 경우에만 목록 폭에48을 더한다.

- **목록:** 외곽 CUI width/height setter만 바꾸면 내부 페이지가 이전 폭·높이를 유지한다. 현재 페이지의 `body+A0` clipping drawable을 `9303B0(clip,width,552)`로 갱신하고 body의 외곽도 맞춘다. 미리보기를 덮는 행과 테두리 밖 마지막 행을 함께 확인한다.
- **스크롤바:** 외곽 높이만 줄이면 아래 화살표·track은 이전 길이에 남는다. 현재 y170/높이520, 내부 `bar+1A4=520` 후 `84CE60`으로 track/thumb/아래 화살표를 재배치한다. 위쪽뿐 아니라 끝까지 내린 상태도 확인한다.
- **미리보기:** 왼쪽 검은 여백은 별도 gutter였다. [native_ccz_preview.inl](../src/native_ccz_preview.inl)의 `kGutter=0`과 canvas/panel 폭 일치를 유지한다. 목록 overflow를 검은 사각형으로 가리지 않는다.
- 레이아웃 수정 후 최소 화면 확인: 첫 행·마지막 행·스크롤 양끝·미리보기 경계·결정/뒤로가 같은 화면에서 함께 보이는지. 모의 검사 통과는 실제 렌더링 증거가 아니다.

## 6. 외교 추가 대응: 판정 보류만으로 UI가 유지되지는 않음

현재 구현: [native_diplomacy_intel.inl](../src/native_diplomacy_intel.inl), [diplomacy_intel_profile.h](../src/diplomacy_intel_profile.h). 기능 설명: [DIPLOMACY_INTEL](DIPLOMACY_INTEL.md).

- 원작 `815EA0`은 판정을 보류해도 뒤에서 인물·footer를 정리할 수 있었다. 기존 gate는 **해당 보류 라운드에 한해** `816756`의 UI 정리 부분을 건너뛰어 `816806`의 기존 정리/소멸 경로로 이어간다. 정리 전체를 조기 return으로 없애지 않는다.
- footer 복구에 일반 `856500`을 쓰면 hidden mode1/2를 건너뛴다. 원작 입력 단계 복귀와 같은 `856620`을 사용한다.
- 좌우 인물 slot3/4는 `83BFD0`으로 pending face-out을 취소하고 face-in 상태를 복구한다.
- 초기 복구 뒤 원작 메시지 완료 콜백이 늦게 퇴장시킬 수 있다. 현재 frame은 **원작 frame 호출 후**, 같은 pending state·추가 대응·phase8일 때만 퇴장 플래그/숨김 mode1/2를 확인해 재복구한다. 매 프레임 입장 연출을 재시작하거나 최종 결과 뒤 인물을 부활시키지 않는다.
- UI 복구와 승패 판정은 분리한다. 추가 대응 완료 후 원작 판정을 한 번만 실행하고 원래 결과 단계·비용·정리를 이어간다.
- 「초상화가 나가니 이미 승패가 정해졌다」는 추정은 이 재현의 원인으로 확인되지 않았다. 원작 `811210`에서 결과12/13은 인물/버튼 퇴장 완료를 기다려 결과 적용으로 넘어간다. 퇴장 관찰만으로 난수 시점을 판단하지 않는다.
- 13:43 재현 로그는 첫 판정 보류54 → 추가 투입803 → 상대 확률33 → 원작 draw6<33 → 상대 성공을 보여 줬다. RNG는 추가 투입 뒤1회였다. 방어67%가 실패하는 것은 가능한 결과다. 사용자는 이후 상대3%에서 반환 거부를 확인했다. **포로 소속 변경 함수의 정확한 실행 시각까지 직접 기록한 것은 아니다.**
- v15.3에서는 사용자 결정으로 **100% 초과 투입을 중지**, 원작 한도·보조 표식을 복원했다. 마지막 추가 대응은 유지한다. 초과 투입을 버그 수정 명목으로 다시 켜지 않는다.

## 7. 원인을 못 찾을 때: 좌표 추측 대신 좁은 호출 래퍼

- 기존 [native_ui_call_trace.inl](../src/native_ui_call_trace.inl)과 [inspect_ccz_ui_trace.py](../tools/inspect_ccz_ui_trace.py)를 재사용한다. 생성·설정·콜백 등록·모달 enqueue·첫 frame을 구분해 **호출 전/정상 복귀**, 대상 객체·스레드·상태·footer/list/bar identity를 남긴다. 호출이 찍혔다는 것과 반환했다는 것을 구분한다.
- ABI가 확인된 동일 인자를 같은 원래 스레드에서 전달하고 원작을 정확히 한 번 호출한다. 관찰 때문에 반환값·난수 횟수·소유권·호출 순서를 바꾸지 않는다. 외부 메모리 쓰기/원격 함수 호출은 UI 수리 방법이 아니다.
- 외교 진단의 실패 사례: 입력 thread23272와 최종 native 처리 thread27208이 달라 입력 스레드 필터가 RNG 로그를 버렸다. **로그 누락은 함수 미호출의 증거가 아니었다.**
- 성공한 진단 보정은 원작 frame/resolve 호출 범위에 `TraceScope`를 두고 해당 pending state의 TLS 스코프도 소유자로 인정한 것. 실제 게임 호출 스레드를 옮긴 것이 아니다. 관계없는 worker를 허용하지 않으며 스코프 종료/예외 때 이전 값을 복구한다.
- 외교 비교는 `resolve_deferred → final_scores/final_spent → resolve_enter → rng_roll → resolve_return → done`을 같은 교섭으로 묶는다. 숫자가 상대 확률인지 플레이어 확률인지 먼저 확인한다.
- 프레임 로그는 기존 표본 제한을 유지한다. 진단 코드는 `NO_RUNTIME_LOG`에서 제외한다. 실행하지 않은 관찰이나 기록되지 않은 원인을 성공 근거로 쓰지 않는다.

## 8. 다음 수정의 최소 완료 기준

1. 사용자 증상 하나를 고르고 관련 함수·이 문서의 해당 항목만 확인한다. 원인이 불명확한데 여러 UI 모드/소유권/배치를 한꺼번에 바꾸지 않는다.
2. 생성 시점·선택·저장·렌더 경계 중 어디가 문제인지 먼저 나눈다. 이미 해결된 다른 영역은 보존한다. 조조전 local14 `ccz_sprites_zoom_fallback` 렌더링 복구는 이 UI 작업과 무관하며 제거/비활성화하지 않는다.
3. 해당 회귀만 확인한다: 선택 가능, 결정/뒤로, 저장/취소, 닫고 다시 열기, 목록 양끝·미리보기 경계. 코드 변경에는 기존 필수 빌드 규칙을 따르되 문서만 수정하면 빌드·설치를 하지 않는다.
4. 설치 전후 DLL/manifest 해시로 **같은 후보를 실제 설치했는지** 확인한다. 진단판·무로그판·공개 ZIP을 혼동하지 않는다. 해시 검사를 끄거나 DLL만 수동 복사하지 않는다.
5. 보고에 소스 확인 / 모의 검사 / 빌드·설치 / 사용자 실게임 확인을 분리한다. 같은 실패가 재현되면 직전 실패 접근을 반복하지 말고 호출 전후 기록으로 다음 분기점을 찾는다.
