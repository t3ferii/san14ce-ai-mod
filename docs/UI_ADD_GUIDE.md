## 정답 요약 (이대로 만들면 보인다)

**옆에 있는 원작 버튼 하나를 그대로 복제한다.** 노드·크기·생성 인자·생성 시점을 모두 그 버튼과 같게 하고, 위치(x)와 글자만 바꾼다.

1. **화면 자료(ScreenLayout)에 노드 추가** — 옆 버튼 노드를 하위 노드까지 통째로 복사한다. 새 노드 ID는 맨 끝 번호를 쓰고 x만 옮긴다. 부모의 자식 수를 +1 한다. 크기는 옆 버튼과 같게 둔다(아래 4번).
2. **생성 인자는 옆 버튼을 원작이 만드는 호출과 같게** — `92E430(layout+0x130, 새 노드, style, kind, 1, 0)`. 옆 버튼을 만드는 원작 CALL을 디스어셈블해서 style·kind를 그대로 복사한다.
   - 숙련 표준 버튼: `5F150C: 92E430(pane+130, 12, 3, 0, 1, 0)` → 순환 버튼은 `(…, 48, 3, 0, 1, 0)`.
   - 반란: `92E430(bar+130, 0x18, 2, 0, 1, 0)`.
3. **생성 시점은 원작 버튼 생성 도중** — 원작이 같은 화면의 다른 버튼을 만드는 CALL 하나를 감싸고, 그 직후에 만든다. 화면 구성 함수가 끝난 뒤에 만들면 생성·등록은 되지만 안 보일 수 있다(반란 2026-10-23).
4. **너비는 그 스킨을 원작이 쓰는 최소 너비 이상** — `python -B -X utf8 research/ui_atlas/button_styles.py <스킨>`. hanyou_defo는 원작 최소 108, 라디오는 96이다. 너비 48에서는 9분할 가장자리(46+46)만 남아 어둡게 뭉개졌다. 공간이 모자라면 버튼 수를 줄인다(순환 버튼 1개).
5. **글자·클릭** — 글자는 `85C9C0(btn,text)` 또는 `btn vt+0x1D8`. 클릭 값은 `btn+0x80`(값), `+0x84=1`, `+0x88`(키), `+0x8C=1`. 그다음 로컬 functor를 `1A3CB0(btn,0x7FFFFFFE,&local)`로 등록한다. 클릭은 그 화면의 원작 이벤트 함수 앞에서 모드 키만 가로채고, 나머지는 원작으로 넘긴다.
6. **숨김은 필요할 때만** — 만들자마자 `8741D0(btn,0)`으로 숨겼다가 나중에 `8741D0(btn,1)`로 보이면 배경 부품 1~14가 숨김으로 남고 글자만 보인다(local8~9). 원작 버튼처럼 보이는 상태로 만들고, 그 기능을 쓰지 않는 행에서만 숨긴다.
7. **선택 표시는 글자로** — 일반 버튼(kind 0, 84ABA0)은 0x198바이트다. 라디오 setter `85AD20`은 +0x198에 쓰므로 일반 버튼에 쓰면 객체 밖 메모리를 덮어쓴다. 선택 상태는 글자(`[중]`, `소`/`중`/`대`)로 보여 준다.
8. **화면 자료 버전 검사** — DLL은 노드 수가 정확히 맞는 화면 자료에서만 버튼을 만든다(숙련: `table+0x10 == 53`). 화면 자료와 DLL 버전이 엇갈리면 버튼 없이 원작대로 동작한다.

## 런타임으로 만드는 UI는 Layout DLL에 맡긴다 (2026-11-07 사용자 규칙, 모든 새 모드에 적용)

"모드를 만들 때 레이아웃 생성은 Layout DLL에 기록하고 해당 기능 체크/해제 종속성을 만들어야 한다."

- UI는 기능으로 들어가는 진입점, 기능은 눌렀을 때 도는 동작이다. **진입점(버튼·창·토글)의 생성·위치·보임·소멸은 `SAN14_Layout.dll`이 한다.** 기능 모듈은 동작(클릭이 하는 일·글자·데이터)만 갖고 `layout_client::ui_*`로 요청한다.
- 종속성은 기능 스위치 하나다: `layout_client::UiScope scope("<owner>")`는 그 owner의 `layout_registry.h` 훅이 게시됐을 때만 열린다. 꺼져 있거나 게시되지 않았으면 아무것도 만들지 않고 원작 화면이 그대로다. 새 설정 키를 만들지 않는다.
- 만든 직후: 컨트롤을 다 만든 뒤 `ui_activate(pane)`(원작 `vt+0x38`)을 불러야 보인다. 화면 떠남 훅에서 원래 떠남보다 먼저 `ui_release(owner,next)`를 부른다(원작 `vt+0x40` → `vt+0x28(obj,next)` → `vt[0](obj,1)`). 숨겨 두고 버리지 않는다.
- 위 1~8번(옆 버튼 복제 방식)은 그대로 유효하다. 푸터처럼 원작 표에 노드가 있으면 `ui_button`(= `92E430` 복제), 새 창은 `ui_window`(descriptor 창 `870410`).
- 절차와 근거: `docs/UI_RESOURCE_LIFECYCLE.md` 10항, 예 `src/native_tactic_priority*.inl`, 근거 `docs/TACTIC_PRIORITY_V2_PLAN.md` 12.5~12.7.

### 버튼 종류(kind)와 스타일(style)
- kind(92E430 인자4): 0/기타 = `84ABA0` 일반 버튼(0x198) · 1 = `84B2D0` 라디오(84ABA0 + 선택값 +0x198, vt 141409E60, 0x1A0) · 2 = `84B670`(0x1A0) · 3 = 84B670 + vt 13E4400.
- style(인자3) 번호와 스킨 이름: `button_styles.py`가 출력한다. 0 ft · 1 ft_cn · 2 hanyou · **3 hanyou_defo**(표준 버튼) · 4 hanyou_l · 5 hanyou_s · 6 hanyou_s_check · 7 icon · 8~13 tab 계열 · 14~15 yesno_pk · 16~17 pad_win 화살표 · 21~23 radio_s_l/c/r.
- 원작이 실제로 쓰는 (kind, style) 조합만 쓴다. 확인된 실패 조합:
  - kind 1 + style 3 또는 21~23: 숙련 숫자 행에서 안 보임(local4~7).
  - kind 0 + style 5: 클릭하면 튕김(`ADC009` 주소 0x2 쓰기, local9).

## 안 보일 때 진단 순서 (추측으로 고치지 않는다)

게임을 켠 채 **읽기 전용**으로 관찰한다(`tools/inspect_expert_runtime.py`가 예시: OpenProcess 0x410 + ReadProcessMemory만). 같은 화면에서 **보이는 원작 버튼과 새 버튼을 나란히** 비교한다.

| 비교 항목 | 위치 | 정상 기준 |
|---|---|---|
| 화면 자료 로드 | `layout+0x130 +0x10` 노드 수 | 패치한 노드 수 |
| 생성·등록 | 전역 등록 목록, 패널 출력층(`pane+0x160`) 항목 `{id,order,control}` | 옆 버튼과 같은 목록에 있음 |
| 표시·활성 | `btn+0x40` bit0 표시(8741D0), bit2 활성(141E0) | 옆 버튼과 같음 |
| 위치·크기 | `btn+0x20/+0x24/+0x28/+0x2C` | 의도한 자리, 원작 최소 너비 이상 |
| 그림 부품 17개 | `btn+0x138[i]` 설명자의 `+0x10C~+0x10D` 표시 바이트 | 모두 `11`(배경 1~14가 `00`이면 숨김 고착) |
| 부품 크기 | 설명자 `+0xF0` w,h | 너비에 비례. 9분할 가장자리 합보다 큰지 |

교체된 노드의 레이아웃 설명자는 해제되고 컨트롤이 자기 스타일 부품으로 그린다. **화면 자료의 하위 그림 노드는 출력에 쓰이지 않는다.** 노드는 위치·크기만 정한다(local7로 확인).

"생성됨·등록됨·클릭됨"은 화면 출력의 증거가 아니다. 사용자 화면 확인 전에는 완료로 보고하지 않는다.

## 화면 자료 패치에서 튕김을 만든 결함 (반복 금지)
- LCSK 머리 `+20`은 u16 노드 수다. u32로 쓰면 옆 `+22`(값 2)가 0이 되어 진입할 때 튕긴다(local3, AEAF49).
- 블록 순서(예: `0,1,3,4,5,9,2`)를 정렬하지 않는다.
- 머리 `+24/+26/+28/+30` = 88/144/224/736바이트 노드 수. 하위 노드까지 복사했으면 종류별로 맞춘다. 736바이트 그림 노드를 복사하면 k1의 표4·표5(9분할 슬롯, 표4 항목 +6은 자기 슬롯 번호)에 슬롯 9칸을 새 번호로 추가한다.
- 이미 설치된 화면 항목을 다시 만들 때는 새 묶음 json에 `replaces_ktids`를 적는다(`install_local.py --layout`).

## 0. 먼저 정할 것 (사용자 기준)
- 버튼은 **원작 네이티브 버튼**으로 만든다. 옆 버튼과 같은 글꼴·모양이어야 한다. D3D 오버레이(통합 인사 버튼)·길게 누르기 같은 숨은 조작은 거절된 방식이다.
- 위치는 사용자 스크린샷의 "어느 버튼 옆"을 기준으로 정한다. 기존 버튼의 기능을 바꾸지 않는다.

함수 디컴파일은 먼저 `tools/decomp_cache.py get <주소>`로 찾는다. 없을 때만 REA를 부른다([SESSION_RULES 7](SESSION_RULES.md)).

## 1. 화면 생성 함수 → 버튼 막대 객체 (10분)
1. 화면 상태(State)의 vtable을 RTTI로 찾는다. `atlas.py class '<클래스>@@'`. 예: CPersonSelectState 13E5018.
2. 그 화면을 구성하는 함수에서 `alloc → 생성자 → vt+0x188(layout,..)` 패턴을 찾는다. 0x188 슬롯이 레이아웃 이름 문자열을 쓴다. 예: CCmnFooter vt+0x188 = 850A10, 레이아웃 이름 `"cmn_footer_re_cn"`.
3. 기존 버튼에 텍스트를 넣는 호출(예: `85FEF0(bar,idx,text)`)과 그 안의 실제 생성 함수(85FCE0)를 디컴파일한다. **허용 idx 검사**가 있으면(85FCE0은 1..5, 0xE, 0x11, 0x12만) 빈 슬롯이 없다. 이 경우 바로 4단계(레이아웃 노드 추가)로 간다.

## 2. 레이아웃 KTID 찾기 (이름→KTID 표는 없음)
- `atlas.py search <레이아웃 이름>`은 문자열만 준다. KTID 변환표는 아직 없다.
- 대신 `research/ui_atlas/layout_nodes.jsonl`에서 **노드 번호 패턴**으로 찾는다. 코드가 쓰는 idx(예: 0xE/0x11/0x12/0x15)가 모두 있고, 노드 수가 비슷하며, 이름에 `btn`/`Preset_cmn_btn_*`가 있는 레이아웃을 고른다(아래 파이썬 한 번이면 된다).
  - 예: 하단 바 = 3633396402 (0xD8913AB2, `_cn` 판, 0xF=`cmn_badge_cn`). 같은 모양의 `cmn_footer_re`(2867782876/3773945012)는 버튼이 0xE/0xF/0x10이라 다르다. **코드의 idx와 맞는 쪽을 고른다.**
- 본문: `research/ui_atlas/layout_bodies/<KTID hex>.lcsk`. 구조 덤프 스크립트는 `research/speed_buttons/build_patch.py`의 `lcsk_sections`/노드 분할 코드를 그대로 쓴다.

## 3. 노드·생성 함수의 의미
- `92E430(table=layout+0x130, idx, style, kind, 1, 0)`이 노드 idx 자리에 컨트롤을 만든다. **노드 이름은 쓰지 않고 위치·크기만 쓴다.** `Preset_*` 노드는 88바이트(0x58) 빈 노드다.
- kind·style 표는 위 「버튼 종류와 스타일」을 따른다(예전의 「1=아이콘」 설명은 틀렸다. 1은 라디오다, 2026-10-24 REA).
- 텍스트는 `btn vt+0x1D8(btn,text)`로 넣는다. 클릭 id는 `btn+0x80=idx`, `btn+0x84=1`이다.
- 클릭은 로컬 functor(`[0]=vtable,[8]=소유자,[0x38]=&local`)를 `1A3CB0(btn,0x7FFFFFFE,&local)`로 등록한다. 1A3CB0은 복사 후 로컬 functor를 스스로 소멸시킨다. 반면 `867300`을 직접 쓰면 speed_buttons처럼 vt+0x20 소멸을 직접 호출해야 한다.
- 보이기·숨기기: `92F810(table,idx,flag)`. 버튼 활성: `85AAD0(bar,idx,enabled)`. 툴팁: `89B110`.

## 4. 레이아웃 노드 추가 (ScreenLayout 패치)
- 기존 파이프라인: `research/speed_buttons/build_patch.py` → `layout_patch/traits9_layout.bin/.json`. 이 결과가 `build/input_package/`에 들어가고, manifest의 `layout_patch.bank_sha256/json_sha256`과 일치해야 한다.
- 88바이트 노드 하나 추가:
  - 이웃 노드 레코드를 복사하고, `+0/+2` id와 `+8` x(float)를 바꾼다. 부모의 `+54` 자식 수를 +1 한다.
  - k1 이름표(kind 1)에 새 이름을 추가한다. k1 머리에서 total(+4), nsize(+8), xsize(+12), count(+18 u16)를 고치고, +24는 hsize+nsize로 맞춘다.
  - LCSK 머리에서 +8(전체 크기), +20(노드 수)을 고치고, +24(0x58 레코드 수)를 +1 한다. 0x90 이미지 노드면 +26을 고친다.
- 엔트리는 `idrk_entry`(16KB zlib 조각 + 0 조각 + CRC)로 만든다. 원본 인덱스 엔트리는 pristine 백업 기준이다.
- 기존 묶음에 엔트리를 덧붙이는 예: `research/lord_change/build_footer.py`(현재 묶음을 접두로 그대로 두고 footer 엔트리 추가, 다른 노드·이름표·섹션 불변 자체 검사). 원본 인덱스 엔트리는 설치된 `ScreenLayout.rdb`의 현재 엔트리(다른 모드가 안 바꾼 KTID)를 쓴다.
- 설치: `tools/install_local.py prepare ... --layout <폴더>`가 스테이지의 묶음과 manifest 해시를 바꾸고, 이때만 설치 후 `ScreenLayout.rdb` 색인 변경을 허용한다(2026-10-23). SplitManage는 이전 묶음 번호를 재사용해 기존 8개 엔트리를 되돌린 뒤 새 기록 전체를 다시 연결한다.

## 5. 연결 위치 (코드)
- 화면 구성 함수가 끝난 뒤 같은 UI 스레드에서 버튼을 추가한다. 화면 함수 호출 1곳은 CallLink로 감싸거나, vtable 슬롯은 patch_pointer를 쓴다.
- 클릭은 소유 화면의 click functor invoke(예: 13F52F0)를 디컴파일해 idx 분기를 찾고, 새 idx만 가로챈다. 원작 idx는 그대로 넘긴다.
  - std::function vtable은 [0]복사 [1]이동 [2]호출 [4]소멸. 하단 바 functor 146D8A0의 호출(8604B0)은 bar+80=id 후 이벤트 0x578, 화면 functor 13F52F0의 호출(7A8580)은 `state vt+0x70(state,bar)`로 넘긴다. 세력선택은 533570이 `bar+80` switch → 이 vtable 슬롯(13E5088)을 patch_pointer로 감싸면 된다.
- 무장 고르기는 자동등용과 같은 원작 목록 선택(250EA0 설정, +0 대상 목록, +18=2, +1C 최대 수, +28 제목, +80 결과 목록, 45B620/45BE60 모달, 251A10 해제)을 쓴다. +40/+78 판정 functor는 생략 가능(250EA0 기본값 0).
- 확인창: `216090(text)`가 bool을 돌려준다(예/아니요).

## 6. 시간 낭비였던 것 (반복 금지)
- 숙련 소·중·대(2026-10-24~25): 생성 시점 이동, parts Begin/End 수동 호출, 스킨 번호만 교체, 하위 노드 복제를 차례로 시도했고 모두 화면에 변화가 없었다. 실행 중에 보이는 원작 버튼과 나란히 비교하자 원인(라디오 종류, 숨김 고착, 너비)이 바로 나왔다. 처음부터 「안 보일 때 진단 순서」를 따른다.
- 길게 누르기·OS 입력 스레드: 게임 안에서 반응이 없었고 사용자도 찾기 어렵다.
- 오버레이 버튼 재사용: 폰트와 모양이 달라 거절됐다.
- atlas에서 이름으로 KTID를 찾는 시도: 표가 없다. 2단계의 노드 패턴 검색이 바로 된다.
- `CodeLink`는 16바이트 블록 안 오프셋이 11 이하일 때만 쓸 수 있다. 블록 경계를 넘는 call에는 CallLink를 쓴다.
- 레퍼런스 모드(`reference_mod/SAN14CE 1.6 모드모음`)의 버튼 방식은 참고만 한다(빈 탭 칸 재사용 등). 바이너리는 실행하지 않는다.
- REA를 함수마다 따로 부르는 것: 새 세션마다 EXE 전체 분석(수 분)을 다시 한다. 캐시를 먼저 보고, 없는 주소만 한 번에 묶어 부른다.
