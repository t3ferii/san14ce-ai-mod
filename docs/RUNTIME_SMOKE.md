# 실게임 최소 확인 (한 번 실행으로 "전과 같이 동작" 확인)

사용자 요청 2026-11-16. 리팩토링이나 내부 정리 뒤에, 게임을 **한 번** 짧게 실행해서 기능이 전과 같이 설치·동작하는지 진단 로그로 확인한다. 진단판(`build_split.ps1 -RuntimeDiagnostics`, 설치 시 `--diagnostics-on`)이어야 로그가 남는다.

## 1. 무엇을 재나

도구: `tools/runtime_smoke.py`. 게임 폴더의 진단 로그만 읽는다. 게임·메모리·파일은 건드리지 않는다.

| 로그 | 쓰는 쪽 |
|---|---|
| `SAN14_AITactics.log` (+ `.old.log`) | 로더·편의·Layout·CCZ·ModPack |
| `SAN14_CombatAI.log` (+ `.old.log`) | 전투 AI |

한 줄 형식: `날짜 시각 day=<게임 날짜> thread=<스레드> <사건> army=<값1> value=<값2>`. `day=-1`은 게임 날짜 전, 곧 설치·시작 단계다. 실행 한 번 = `day=-1` 묶음부터 다음 `day=-1` 묶음 전까지.

기준 실행과 이번 실행을 세 가지로 비교한다.

1. **설치 결과**: 기준 실행의 `*_installed`·`*_registered`·`*_ready`·`*_published`·`*_link` 같은 시작 기록이 이번에도 모두 있어야 한다. 없으면 "문제". 첫 값(army: 켜짐·개수)이 바뀌면 "확인할 차이". 시간·CPU 계측과 스레드 번호는 비교하지 않는다.
2. **실패 신호**: fail·mismatch·disabled·unavailable·engine_off·rollback 같은 사건이 새로 생기거나 크게 늘면 "문제". 오류 진단 줄(`native_exception_first_chance`)도 센다.
3. **활동**: 기준 실행이 첫 30일(두 실행이 함께 진행한 날짜까지) 안에 3번 이상 남긴 사건이 이번에도 있어야 한다. 없으면 "확인할 차이". 플레이어가 그 행동을 하지 않았을 때도 생기므로, 아래 2절의 행동을 하면 줄어든다.

알려진 의도된 차이는 도구의 `EXPECTED` 표에 사유와 함께 둔다. 예: local194에서 `tactic_priority_installed`의 둘째 값을 뺐다.

## 2. 게임에서 할 일 (10~15분)

현재 기준 실행은 2026-11-15 17:00 실행(local183, 553일 진행)이다. 가능하면 **그때와 같은 세이브**로 한다. 설정(`기능설정.ini`)은 바꾸지 않는다.

1. 게임을 켠다. 타이틀 화면에서 버튼이 원래 자리에 다 있는지 본다.
2. 세이브를 불러온다.
3. **속도 ×8로 30일 이상** 진행한다. 월초를 한 번 넘긴다. 컴퓨터 AI 출진·건설·자동 내정·4계절 날씨·지형 진행이 여기서 기록된다.
4. 그동안 지도를 본다.
   - 계절 색과 비·구름이 보이는가.
   - 강·바다 물거품과 나무가 정상인가.
   - 깜빡임이나 검은 칸은 없는가.
5. **군사보고**를 연다. 카드가 보이는지 확인하고 「부동산 개발」 버튼을 눌렀다 닫는다.
6. **인사**에서 여러 명을 골라 등용을 한 번 하고, 탐색 조건 화면을 열어 본다. 등용 가능성 문구가 보이는지 확인한다.
7. 내 부대 하나를 클릭해 정보창과 예상 피해량 표시를 본다.
8. **저장**한 뒤 게임을 끈다. 논공·창고·전법 기억·매복·사거리 기록이 저장 단계에서 남는다.

튕기거나 멈추면 그 시각과 하던 행동만 알려 주면 된다.

## 3. 결과 보기

게임을 끈 뒤 `AI_TacticsMod` 폴더에서 아래를 실행한다. "게임 했어"라고만 알려 주면 Claude가 대신 실행하고 해석한다.

```powershell
python -X utf8 tools/runtime_smoke.py sessions     # 이번 실행이 목록 맨 아래에 있는지
python -X utf8 tools/runtime_smoke.py compare      # 기준 실행과 비교 (종료 코드 0 = 문제 없음)
```

- **문제**: 설치 기록이 빠졌거나 실패 신호가 새로 생긴 것이다. 해당 기능의 소스와 가드부터 본다.
- **확인할 차이**: 값이 바뀌었거나 행동을 안 해서 기록이 없는 것이다. 의도된 변경이면 `EXPECTED`에 사유를 적고, 아니면 그 기능을 다시 확인한다.
- 이번 실행이 좋으면 새 기준으로 저장한다: `python -X utf8 tools/runtime_smoke.py snapshot`. 기준 파일은 `data/diagnostics/smoke_baseline.json`이다.

## 4. 한계

- 로그에 남지 않는 것(그림이 맞는지, 글자 위치)은 2절의 눈 확인으로만 본다.
- 전투 AI 판단처럼 날짜가 지나야 생기는 사건은 30일 안에 안 나올 수 있다. 그런 사건은 "확인할 차이"로만 나온다.
- 새 기능은 `<기능>_installed` 한 줄을 남겨야 이 비교에 잡힌다([새 기능 규칙](FEATURE_RULES.md) 7절).
